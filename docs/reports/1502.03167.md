## Tested claims

### bn_enables_sigmoid_training

> Batch normalization allows deep networks using saturating sigmoid nonlinearities to be trained successfully, whereas the same architecture without batch normalization fails to train beyond chance-level accuracy.

Source: Sec. 4.2.2 · Metric: top-1 validation accuracy · Expected: BN-x5-Sigmoid accuracy (69.8%) >> Inception-Sigmoid accuracy (~chance, 1/1000)

**Verdict: Consistent at reduced scale**

bn_x5_sigmoid: 0.9267 (sd 0.0188, n=5); inception_sigmoid_no_bn: 0.08704 (sd 0.00797, n=5). Effect in the predicted direction: +0.8396 [95% CI +0.823, +0.8541], Welch p=8.1e-10.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** In the Inception-v3-scale experiments (Sec 4.2.2), the authors replace ReLU with sigmoid in a very deep Inception network and show that without batch normalization the network never trains above chance (1/1000 ImageNet accuracy), while adding BN throughout ("BN-x5-Sigmoid") lets the same architecture reach 69.8% top-1 accuracy.

**Reduced setup.** Use sklearn's 8x8 digits dataset (1797 images, 10 classes) standing in for ImageNet. Build a from-scratch numpy MLP that is deep for its size (6 hidden layers of width 64) using sigmoid activations everywhere, trained by plain mini-batch gradient descent (no adaptive optimizer, no learning-rate warmup) for 60 epochs, batch size 32, on a random 70/30 train/test split, using only ~300 training examples (subsampled from the training split) so the network is over-parameterized relative to the data and a train/test gap is possible. Two arms: (1) "sigmoid_no_bn" - the plain 6-layer sigmoid MLP with a fixed, deliberately small-scale weight initialization (matching the paper's Inception-sigmoid setup, which used no special init tricks) so that saturation/vanishing gradients dominate; (2) "bn_sigmoid" - identical architecture and training loop but with a batch normalization layer (mean/variance normalize + learnable scale/shift, computed from scratch in numpy) inserted before each sigmoid activation. Both arms use identical data, initialization scheme (same random seed draws for weights, only differing by the BN layer's extra scale/shift params initialized to 1/0), batch size, epochs, and learning rate. Report top-1 test accuracy at the end of training, averaged over 5 seeds per arm.

**Why the claim should transfer.** The claim is fundamentally about a training-dynamics mechanism: sigmoid nonlinearities saturate outside a narrow input range, and when many sigmoid layers are stacked, gradients passing back through them shrink multiplicatively, stalling learning; BN counteracts this by keeping pre-activations in a well-conditioned range at every layer, restoring gradient flow. This mechanism does not depend on ImageNet's scale, label count, or the Inception topology -- it depends only on (a) having enough stacked sigmoid layers for compounding saturation to occur, and (b) initialization/data scale that puts the no-BN network into the saturated regime. A 6-layer sigmoid MLP with modest width, on a real (if small) 10-class image-like task with limited training data, is deep enough that plain SGD through unnormalized sigmoids is expected to get stuck (small/vanishing gradients keep outputs near uniform, i.e., near chance-level ~10% accuracy on digits), while the same architecture with BN before each sigmoid should train to substantially higher accuracy in the same number of updates. Keeping the data modest (300 examples) and skipping any learning-rate tuning or warmup ensures the no-BN arm isn't rescued by an easy, quickly-solvable task or by an optimizer smoothing over the saturation problem. If BN's test accuracy is dramatically higher than the no-BN arm's (near chance) across 5 seeds, that reproduces the qualitative direction of the paper's finding; if both arms train similarly or both fail, the reduction was not informative and that would be reported as such.

**Seeds per arm:** 5 · **Estimated cost:** 45 min · **Code source:** from_scratch

**Changes from the paper**

- Dataset: 8x8 digits (1797 images, 10 classes) replaces ImageNet (1000 classes, ~1.2M images) -- the claim is about a training-dynamics mechanism (sigmoid saturation blocking gradient flow vs BN restoring it), not about ImageNet-scale visual complexity, so any small classification task with enough depth to induce saturation is a valid testbed.
- Architecture: 6-layer numpy MLP (width 64) replaces Inception-v3 -- depth (not the specific inception topology) is what causes compounding sigmoid saturation across layers; a plain deep MLP preserves 'many stacked sigmoid layers' which is the mechanism BN is claimed to fix, while being tractable to hand-write in numpy on CPU.
- Optimizer: plain mini-batch SGD instead of the paper's RMSProp-style optimizer -- the failure mode (vanishing gradients through saturated sigmoids) is an optimizer-agnostic property of the activation/depth combination; using a simpler optimizer keeps the comparison clean and doesn't advantage either arm since both use the same optimizer.
- Training set size reduced to ~300 examples (subsampled from the 70% split) -- shrinking the data relative to network capacity (10 classes, 6x64 hidden units) keeps the model over-parameterized enough that a train/test gap and genuine optimization difficulty are possible, rather than the task being trivially solvable in a couple epochs regardless of activation.
- Epoch count fixed at 60 (small, CPU-feasible) instead of the paper's many thousands of steps at ImageNet scale -- 60 epochs over 300 examples with batch size 32 gives ~560 gradient updates, enough for a working sigmoid+BN network to converge on a 10-class 8x8 task while remaining fast enough that a non-BN sigmoid net's failure to move off chance is still observable within budget.
- BN implemented from scratch in numpy (mean/var normalization + learnable scale/shift, following the standard BN formula) since no deep learning framework is available -- this preserves the actual mechanism (normalizing pre-activations per mini-batch) rather than substituting a different regularizer.

**Deliberately preserved**

- The core architectural element under test: multiple stacked sigmoid nonlinearities in a deep(ish) network, which is what makes gradients prone to vanishing/saturation.
- The exact placement of BN (before each sigmoid activation) as prescribed by the paper's mechanism.
- Identical initialization scale, data, batch size, epoch count, and learning rate between arms -- the only architectural difference is presence/absence of BN layers.
- A training regime (small data relative to capacity, no early stopping) where the network is not trivially solved by a couple of gradient steps, leaving room for a training-dynamics effect to manifest.
- Use of an unmodified sigmoid activation function (not a leaky or scaled variant) so saturation behavior matches the paper's setting.

### bn_mnist_faster_higher_accuracy

> On the MNIST digit classification task, adding batch normalization to a simple fully-connected sigmoid network results in faster training and higher test accuracy compared to the same network without batch normalization.

Source: Sec. 4.1, Fig. 1(a) · Metric: test accuracy vs training steps · Expected: with_BN accuracy > without_BN accuracy

**Verdict: Consistent at reduced scale**

mnist_with_bn: 0.9381 (sd 0.0106, n=5); mnist_without_bn: 0.7881 (sd 0.0552, n=5). Effect in the predicted direction: +0.15 [95% CI +0.1082, +0.1948], Welch p=0.00314.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** On full MNIST (60k train / 10k test, 28x28 grayscale digits), the paper trains a simple fully-connected sigmoid network (multiple hidden layers of sigmoid units) with and without batch normalization inserted before the nonlinearity, and shows BN reaches higher test accuracy in fewer training steps (Fig. 1(a)).

**Reduced setup.** Use sklearn's 8x8 digits dataset (1797 images, 10 classes) as a stand-in for MNIST. Split into a small train set (300 images) and a held-out test set (remaining ~1497 images) to induce a visible train/test gap. Build a from-scratch numpy fully-connected network: input(64) -> hidden(128, sigmoid) -> hidden(128, sigmoid) -> output(10, softmax), trained with plain mini-batch SGD (batch size 32, fixed learning rate) for 300 steps. Two arms: (a) with BN -- a hand-written batchnorm (normalize pre-activation using batch mean/var, learnable scale/shift, running stats for eval) inserted before each sigmoid; (b) without BN -- identical network, same forward/backward code path, BN layer replaced by identity. Record train and test accuracy every 10 steps for both arms, 5 seeds each (varying weight init and batch shuffling only).

**Why the claim should transfer.** BN's claimed mechanism -- reducing internal covariate shift / stabilizing the distribution of sigmoid pre-activations so gradients stay in a well-conditioned regime -- is architecture- and mechanism-level, not dataset-scale-level: it should help any sufficiently deep sigmoid network trained with plain SGD, regardless of whether the input is 28x28 or 8x8 pixels. The reduced setup keeps every element the mechanism needs: multiple sigmoid layers prone to saturation, a nontrivial multi-class task, and a training budget short enough that convergence speed differences are visible rather than washed out by both arms eventually reaching ceiling accuracy. Shrinking the training set to 300 examples deliberately creates the train/test gap and task difficulty needed so that 'higher test accuracy' is a meaningful, non-trivial outcome rather than both arms saturating at ~100%. If BN's convergence-speed and generalization benefits are real and scale-free, the with-BN arm should show both a faster rise in train/test accuracy over the 300 steps and a higher final test accuracy than the without-BN arm; if the effect is purely an artifact of MNIST's specific scale or the paper's specific hyperparameters, it may not appear here, which is itself informative.

**Seeds per arm:** 5 · **Estimated cost:** 25 min · **Code source:** from_scratch

**Changes from the paper**

- MNIST (28x28, 70k images) replaced by sklearn 8x8 digits (1797 images) -- resolution and image statistics differ but the claim's mechanism (BN stabilizing sigmoid pre-activation distributions to speed convergence and reduce saturation) does not depend on image size, only on having a nontrivial multi-class classification task with sigmoid units susceptible to saturation.
- Train set shrunk to 300 examples (instead of 60k) -- deliberately induces a visible train/test gap and makes the classification problem harder relative to model capacity so that training speed and generalization differences have room to appear within a short run; a network this size on the full 1797 samples would already solve the task near-perfectly for both arms, hiding the effect.
- Training length shortened to 300 SGD steps (instead of the thousands/tens-of-thousands in the paper) -- BN's main claimed advantage is faster convergence, so if the effect is real it should already show as a gap in accuracy-vs-step curves within a few hundred steps on a small network; this preserves the 'faster training' half of the claim while fitting the CPU budget.
- Batch normalization implemented by hand in numpy rather than using a framework layer -- no deep learning framework is available, and a minimal BN (per-batch mean/var normalization plus learnable affine, running stats for eval) is exactly the mechanism the paper describes, not a different method.
- Network narrowed to 2 hidden layers of 128 units (rather than paper's exact depth/width) -- keeps the same sigmoid fully-connected architecture family and multi-layer depth needed for BN's saturation-mitigation mechanism to matter, while remaining fast to train on CPU.

**Deliberately preserved**

- Fully-connected architecture with sigmoid nonlinearities (not swapped for ReLU or convnet)
- Placement of BN before the sigmoid nonlinearity, matching the paper's design
- Same optimizer (plain mini-batch SGD, no momentum/adaptive tricks) and same fixed learning rate across both arms
- Identical data split, batch size, number of steps, initialization scheme, and code path between the with-BN and without-BN arms -- the only difference is presence vs absence of the BN normalization+affine step
- Multi-class classification objective (cross-entropy over 10 classes), matching the paper's task type

## Claims not tested

- **`bn_reduces_steps_14x`** (comparative) — Applying batch normalization to a state-of-the-art image classification model (Inception) allows it to match the original model's accuracy using 14 times fewer training steps. _Requires reproducing full-scale ImageNet Inception training to reach 72.2% accuracy, which is far beyond a CPU-only 60-minute budget._
- **`bn_ensemble_sota_imagenet`** (absolute) — An ensemble of batch-normalized networks achieves a top-5 validation error of 4.9% (4.8% test error) on ImageNet, surpassing the previous best published result and exceeding human rater accuracy. _This is an absolute headline number (4.9% top-5 error on ImageNet) and by construction cannot be tested at reduced scale._
- **`bn_baseline_beats_inception_half_steps`** (comparative) — Simply adding batch normalization to Inception (BN-Baseline) matches the original network's accuracy in less than half the number of training steps. _Depends on large-scale ImageNet Inception training to a specific accuracy threshold, which cannot fit a CPU-only 60-minute budget._
- **`bn_x30_higher_final_accuracy`** (comparative) — Increasing the learning rate further with batch normalization (BN-x30) results in a higher final validation accuracy (74.8%) than the original Inception model (72.2%), despite training somewhat slower initially than BN-x5. _Requires full ImageNet-scale Inception training to reach reported final accuracies, which is infeasible on CPU within budget._
- **`bn_stabilizes_activation_distributions`** (comparative) — Batch normalization keeps the distribution of sigmoid input activations more stable over the course of training compared to a network without batch normalization, which shows significant shifts in mean and variance. _Activation distribution stability is a mechanistic property of BN that can be measured on the same small MNIST setup within budget._
- **`shuffling_improves_accuracy_1pct`** (ablation) — More thorough shuffling of training examples within shards, enabled as part of the batch-normalized training pipeline, improves validation accuracy by about 1%. _This ablation is tied to the large-scale ImageNet pipeline and shard-based data loading, which cannot be meaningfully reproduced at reduced scale on CPU within budget._
- **`bn_reduces_need_for_dropout`** (ablation) — Removing Dropout from the batch-normalized Inception model speeds up training without increasing overfitting, indicating batch normalization provides a regularization effect that reduces the need for Dropout. _Requires large-scale Inception training on ImageNet to observe overfitting/regularization effects, infeasible within a CPU-only 60-minute budget._
- **`original_inception_lr_increase_diverges`** (ablation) — Increasing the learning rate on the original (non-batch-normalized) Inception model by the same factor used for BN-x5 causes the model parameters to diverge to infinity, unlike the batch-normalized version which trains stably at that higher rate. _Depends on the full-scale Inception architecture and ImageNet training dynamics to observe divergence, which cannot be reproduced within the CPU-only budget._

## How these experiments were run

> **These results were produced without container isolation.** The experiments ran in a restricted subprocess, with network access blocked and resources capped, but not inside a sandbox that can contain what it runs. Treat the results as a demonstration of the pipeline rather than as a trustworthy measurement, and re-run under Docker before relying on them.

## Limitations

Read these results narrowly.

- **A negative result here does not refute the paper.** These experiments run at a fraction of the
  original scale. An effect that disappears when the model, the data, or the training budget shrinks
  may still be real at full scale; that is precisely what reduced-scale testing cannot tell us.
- **A positive result is not a reproduction.** It says the direction of the claim survived
  shrinking, not that the paper's numbers were reproduced.
- **Seed counts are small.** With a handful of seeds per arm, statistical power is low. An
  inconclusive verdict usually means there was not enough evidence either way, not that the effect
  is absent.
- **Absolute claims are never testable this way** and are recorded without being run.
- The reduced experiments were written from the paper's description, so they may differ from the
  authors' implementation in ways that matter.
