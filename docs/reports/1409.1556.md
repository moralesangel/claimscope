## Tested claims

### lrn_no_improvement

> Adding Local Response Normalisation (A-LRN) does not improve accuracy over the same-depth network without normalisation (A).

Source: Table 3, Sec. 4.1 · Metric: top-1/top-5 validation error · Expected: A-LRN ≈ A (no improvement)

**Verdict: Inconclusive**

convnet_A_LRN: 0.08075 (sd 0.0103, n=3); convnet_A: 0.07893 (sd 0.00857, n=3). Effect in the predicted direction: -0.001821 [95% CI -0.01437, +0.01073], Welch p=0.826. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** In the VGG paper (Simonyan & Zisserman), configuration A is an 11-layer ConvNet trained on ImageNet (224x224 RGB images, 1000 classes), and configuration A-LRN adds a Local Response Normalisation layer after the first conv layer. Both are trained with SGD for ~74 epochs on multi-GPU, and top-1/top-5 validation error is compared; A-LRN does not improve over A.

**Reduced setup.** Use sklearn's 8x8 digits dataset (1797 images, 10 classes) as a stand-in for ImageNet/MNIST-scale images. Implement a small numpy convnet by hand: one 3x3 conv layer (8 filters, stride 1, valid padding) + ReLU, followed by a flatten and a single fully-connected softmax output layer -- this is the 'A' arm. The 'A-LRN' arm inserts a Local Response Normalisation step (normalise each feature map's activation by the sum of squares of neighbouring channels at the same spatial location, per the standard LRN formula with k=2, n=5 (or n=min(5, num_channels)), alpha=1e-4, beta=0.75) right after the ReLU, before flattening. Both trained with plain SGD (no momentum, no weight decay, no dropout) via manual forward/backward pass, on a reduced training subset of 150 images (15 per class) to induce overfitting, evaluated on the remaining ~1647 images as a validation set. Train for 60 epochs, batch size 15, fixed learning rate 0.05. Run 3 seeds per arm (6 runs total), each seed controlling weight init and the train/val split. Record top-1 error and top-3 error (substituting for top-5, since we only have 10 classes) at the end of training.

**Why the claim should transfer.** LRN's claimed lack of benefit is a statement about the normalization operation itself: rescaling activations by the local sum of squares across nearby channels does not, in the paper's setting, provide useful regularization or improve generalization for a ConvNet already trained with backprop. This mechanism is architecture-shape-independent -- it operates locally on whatever channel-wise feature map a conv+ReLU produces, whether there are 8 channels on 8x8 digit images or 96 channels on 224x224 ImageNet images. By keeping a real conv+ReLU+LRN pipeline (rather than approximating it away) and by shrinking the training set enough that the small network visibly overfits (a nontrivial train/test gap), we preserve the exact condition under which a normalization scheme would have an opportunity to demonstrate a regularizing/generalization benefit if one existed. If LRN provided a generic normalization benefit that generalizes across scales, we would expect to see at least a directional improvement in validation error here too; the original paper's finding was precisely that no such benefit appears even at large scale, so finding no improvement (or even mild harm) at small scale is consistent evidence in the same direction. The main risk to transfer is that some benefit of LRN might only manifest with many stacked conv layers or after many more training steps -- we flag this as the chief limitation, but note the original ablation itself only inserted LRN after the *first* conv layer, so a single conv-layer analogue is a reasonably faithful shrinkage rather than an unfair one.

**Seeds per arm:** 3 · **Estimated cost:** 25 min · **Code source:** from_scratch

**Changes from the paper**

- Dataset: sklearn 8x8 digits (1797 images) instead of ImageNet -- named explicitly; images are far smaller and grayscale, but the ablation is about whether LRN normalisation across channels helps *given* a conv+ReLU feature map that already shows some train/test gap, and this holds regardless of image resolution or color channels.
- Architecture: 1 conv layer + 1 FC layer instead of 11-layer VGG-A -- depth is reduced to keep CPU-only training in minutes, but LRN operates locally after a conv+ReLU regardless of how many such blocks follow, so its (lack of) effect on a single block is a fair analogue of its effect when inserted after the first conv block in the original network (LRN was only applied after conv1 in A-LRN, not throughout).
- Framework: hand-written numpy forward/backward instead of a GPU deep learning framework -- forced by environment; the LRN formula and gradients are implemented exactly as specified in the original paper (k, n, alpha, beta local normalization across channel groups), preserving the mechanism being tested.
- Training set size cut to 150 images (15/class) instead of ~1.2M ImageNet images -- to induce a visible train/test gap (overfitting) even in this tiny model within our epoch budget, since LRN's claimed lack of benefit is only informative in a regime where the network could in principle benefit from any regularization/normalization effect; with the full 1797-sample set the tiny network would not overfit at all and the comparison would be trivially uninformative.
- Optimizer simplified to plain fixed-LR SGD, no momentum/weight decay/LR schedule -- irrelevant to the specific question of whether LRN changes accuracy at fixed architecture; both arms use identical optimizer settings so the comparison stays fair.
- Metric: top-3 error substituted for top-5 error -- with only 10 classes, top-5 is nearly meaningless (chance level 50%); top-3 preserves the spirit of a coarser accuracy measure alongside top-1.
- Epochs reduced from ~74 to 60 -- chosen to fit CPU budget while still allowing training loss to plateau/overfit on the 150-image subset given the extremely small model capacity.

**Deliberately preserved**

- The exact LRN mechanism (formula, hyperparameters k, n, alpha, beta) applied immediately after a ReLU-activated conv layer, since this is the object of the claim.
- Same architecture, dataset, training subset, epochs, batch size, learning rate, and seeds across both arms -- the only difference is presence/absence of the LRN layer.
- A conv layer (not a pure MLP) as the layer LRN operates on, matching the paper's setting of normalizing across feature maps produced by a convolution.
- A regime with a visible train/test accuracy gap in the baseline (A) arm, so that there is genuine room for a regularizer/normalizer to help if it were going to.
- Comparison via validation top-1 and top-3 error at a matched training budget, matching the paper's evaluation protocol in spirit.

### 3x3_stack_beats_1x1

> Configuration D, which uses 3x3 conv layers throughout, outperforms configuration C, which includes three 1x1 conv layers, despite having the same depth, indicating spatial context matters beyond added non-linearity.

Source: Table 3, Sec. 4.1 · Metric: top-1/top-5 validation error · Expected: D > C

**Verdict: Consistent at reduced scale**

convnet_D: 0.6266 (sd 0.0812, n=3); convnet_C: 0.866 (sd 0.051, n=3). Effect in the predicted direction: +0.2394 [95% CI +0.1519, +0.3242], Welch p=0.018. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** In the VGG paper (Table 3, Sec 4.1), configuration D (all 3x3 conv layers) is compared to configuration C (which replaces some 3x3 convs with three 1x1 convs) at the same depth, trained and evaluated on full-size ImageNet (224x224 images, 1000 classes), with top-1/top-5 validation error as the metric.

**Reduced setup.** Use sklearn's 8x8 digits dataset (1797 images, 10 classes) reshaped to 8x8x1 as a stand-in for ImageNet images. Implement two small from-scratch numpy convnets of matched depth (4 conv "layers" + 1 dense output), differing only in kernel size for the middle two conv layers: convnet_D uses 3x3 convs throughout (with 'same' padding so spatial size is preserved), convnet_C uses 3x3 for the first and last conv but 1x1 for the middle two conv layers (mimicking VGG's config C, which swaps some 3x3 layers for 1x1 while keeping depth identical). Both use ReLU activations, a small number of channels (e.g. 8 -> 16 -> 16 -> 16), global average pooling, and a linear+softmax classifier trained with plain SGD (no momentum, no augmentation, no dropout, no weight decay) for a fixed number of epochs (30) on a random 300-image training subset (to induce a train/test gap and make representational differences matter), evaluated on the remaining ~1497 images as a held-out validation set. Batch size 32. Each arm is run for 3 seeds (weight init + data subset seed varied together, same seeds used for both arms) and we report mean top-1 error (and top-3 error as a stand-in for top-5, since there are only 10 classes) on the held-out set.

**Why the claim should transfer.** The claim's mechanism is that a 3x3 kernel can integrate information from a local neighborhood of pixels, while a 1x1 kernel, even after a nonlinearity, can only re-mix per-pixel channel information -- it can add depth/nonlinearity but cannot capture spatial correlations. This mechanism does not depend on image resolution or class count: it is a property of receptive-field size relative to the input grid. 8x8 digit images still have a 2D spatial structure with local strokes and edges that benefit from neighborhood aggregation (e.g., a horizontal/vertical stroke fragment spans multiple adjacent pixels), so a 3x3 kernel over an 8x8 grid should still have a meaningful advantage over a 1x1 kernel doing the same depth of nonlinear re-mixing. Training on a small subset (300 images) for many epochs without regularization is chosen specifically so that both models can nearly memorize the training set but their validation performance will depend on how well their inductive biases (spatial vs. pointwise) generalize -- this preserves the train/test gap regime needed for representational differences to actually show up in held-out error, rather than both models trivially reaching near-zero error on an easy, large, well-covered training set. Given matched depth, channel width, optimizer, and epochs, any systematic validation-error gap between convnet_D and convnet_C should be attributable to the kernel size difference, and the sign of that gap should reflect the same qualitative advantage of spatial aggregation seen in the paper's full-scale result.

**Seeds per arm:** 3 · **Estimated cost:** 25 min · **Code source:** from_scratch

**Changes from the paper**

- ImageNet -> sklearn 8x8 digits (1797 images) -- ImageNet is unavailable (needs network); digits is the documented stand-in for MNIST-style image classification and is the only image dataset available offline, so this is the only architecture claim we can test at all.
- 224x224 RGB images -> 8x8 grayscale images -- forced by dataset substitution; the claim is about relative spatial-context benefit of 3x3 vs 1x1 kernels, a mechanism that does not depend on absolute image resolution, only on there being >1x1 spatial extent for 3x3 kernels to exploit, which 8x8 still provides.
- 1000-class classification -> 10-class classification -- forced by dataset; direction of a kernel-size ablation is not expected to depend on the number of output classes.
- Very deep VGG-style (11-19 layer) convnets -> shallow 4-conv-layer convnets with small channel counts (8-16) -- forced by CPU-only, from-scratch numpy implementation budget; we preserve the core structural manipulation (some middle layers as 1x1 vs 3x3 at matched depth) which is exactly what the claim is about, just with fewer total layers so it finishes in minutes.
- Full ImageNet training (many epochs, huge dataset) -> 300-image training subset for 30 epochs with plain SGD, no regularization -- necessary to keep runtime small on CPU and, more importantly, to induce a visible train/test gap so that representational capacity/spatial context differences actually matter for generalization rather than both models trivially fitting a large dataset equally well.
- No momentum/weight decay/dropout/augmentation -> plain SGD only -- removes potential confounds from extra regularization interacting differently with 1x1 vs 3x3 architectures; keeps the comparison isolated to the kernel-size manipulation itself, per invariant 1.

**Deliberately preserved**

- Exact depth match between the two arms (same number of conv layers + same dense head) -- this is the central controlled variable in the paper's claim (same depth, different kernel composition).
- The specific manipulation: middle conv layers use 1x1 (configuration C) vs 3x3 (configuration D) kernels, with all other layers, channel widths, activations, and training procedure identical between arms -- isolates spatial context as the only varying factor.
- Same optimizer, learning rate, batch size, number of epochs, weight init scheme, and training/validation split logic across both arms and all seeds -- ensures the only difference between arms is the architectural feature under test (invariant 1).
- Same 3 seeds used identically for both arms, each seed controlling both weight init and the training-subset sampling -- keeps the comparison paired and honest (invariant 2).
- ReLU nonlinearity and a real (if small) spatial extent (>1x1) in the input so that 3x3 convs can actually aggregate spatial context that 1x1 convs cannot -- necessary condition for the effect to exist at all.

## Claims not tested

- **`depth_reduces_error`** (scaling_trend) — Increasing ConvNet depth from 11 layers (config A) to 19 layers (config E) steadily decreases top-1/top-5 classification error, with error saturating at 19 layers. _The claim's effect (depth-driven improvement and saturation) is scale-dependent on ImageNet-size data/models and cannot be verified with a shrunk 60-minute CPU budget, and requires 5 large ImageNet-scale ConvNets._
- **`deep_small_filters_beats_shallow_large_filters`** (comparative) — A deep network with small 3x3 filters (B) outperforms a shallower network using 5x5 filters with equivalent receptive field, by about 7% top-1 error on a center crop. _Both a small deep 3x3-filter net and a shallow 5x5-filter net with matched receptive field can be trained cheaply on CPU on a small dataset, and the qualitative direction (deep small filters winning) is architecture-driven rather than scale-driven._
- **`scale_jitter_training_helps`** (comparative) — Training with scale jittering (S sampled from [256,512]) produces significantly better results than training at a fixed scale (S=256 or S=384), even when tested at a single scale. _Scale jittering vs fixed-scale training can be tested on a small dataset/model with matched budgets, and the direction (data augmentation via multi-scale training helping) is a general regularization effect likely to transfer to small scale._
- **`test_scale_jitter_helps`** (comparative) — Evaluating a model over multiple rescaled versions of the test image (scale jittering at test time) improves performance compared to evaluating at a single test scale. _Multi-scale vs single-scale evaluation of the same trained model is a cheap inference-time ablation that does not require retraining and the direction (multi-scale testing helping) is a general augmentation effect._
- **`multicrop_dense_complementary`** (comparative) — Combining dense evaluation and multi-crop evaluation outperforms either evaluation method used alone. _Comparing multi-crop, dense, and combined evaluation strategies on the same small trained model is a cheap inference-only ablation whose complementary-improvement direction plausibly holds at any scale._
- **`two_model_ensemble_best`** (comparative) — An ensemble of the two best single models (D and E) achieves 7.0% (dense) or 6.8% (dense+multi-crop) top-5 test error, improving over the original 7-network ILSVRC submission's 7.3% error. _This claim is about specific absolute top-5 error percentages from a large-scale ILSVRC submission and cannot be reproduced or meaningfully compared at reduced scale._
- **`single_model_beats_googlenet`** (comparative) — The best single VGG model (configuration E) achieves 7.0% top-5 test error, outperforming a single GoogLeNet model by 0.9 percentage points. _This claim depends on absolute headline numbers from two specific large pretrained ImageNet models (VGG-E and GoogLeNet) that cannot be reproduced or fairly compared at reduced scale._
- **`generalization_state_of_art_caltech256`** (comparative) — VGG Net-D and Net-E features used with a linear SVM outperform prior state-of-the-art methods on Caltech-256 by a large margin (about 8.6%). _This claim relies on large pretrained VGG features and an external baseline system (Chatfield et al. 2014) that cannot be reproduced within a CPU-only reduced-scale budget._

## How these experiments were run

> **These results were produced without container isolation.** The experiments ran in a restricted subprocess, with network access blocked and resources capped, but not inside a sandbox that can contain what it runs. Treat the results as a demonstration of the pipeline rather than as a trustworthy measurement, and re-run under Docker before relying on them.

## Limitations

Read these results narrowly.

- **A negative result here does not refute the paper.** These experiments run at a fraction of the
  original scale. An effect that disappears when the model, the data, or the training budget shrinks
  may still be real at full scale; that is precisely what reduced-scale testing cannot tell us.
- **A positive result is not a reproduction.** It says the direction of the claim survived
  shrinking, not that the paper's numbers were reproduced.
- **Seed counts are small.** With a handful of seeds per arm, statistical power is low. An
  inconclusive verdict usually means there was not enough evidence either way, not that the effect
  is absent.
- **Absolute claims are never testable this way** and are recorded without being run.
- The reduced experiments were written from the paper's description, so they may differ from the
  authors' implementation in ways that matter.
