## Tested claims

### densenet_fewer_params_than_resnet

> DenseNets achieve lower error rates than ResNets while using substantially fewer parameters across CIFAR and SVHN benchmarks.

Source: Table 2 · Metric: test error rate vs parameter count · Expected: DenseNet < ResNet error with fewer params

**Verdict: Not consistent at reduced scale**

treatment: 0.07222 (sd 0.00481, n=3); control: 0.05 (sd 0.0182, n=3). Effect in the predicted direction: -0.02222 [95% CI -0.03889, -0.002778], Welch p=0.162. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** On CIFAR-10/100 and SVHN, DenseNet-BC (100-190 layers, growth rate 12-40) achieves lower test error than ResNets (110-1001 layers) with 2-3x fewer parameters, using deep networks trained for 300 epochs with data augmentation on 32x32 RGB images.

**Reduced setup.** Use sklearn's 8x8 digits dataset (1797 images, 10 classes) standing in for CIFAR-10. Implement two small hand-written numpy feedforward networks with matched depth (~6 weight layers) and comparable total parameter budget: (1) a 'ResNet-style' net with residual (identity) skip connections every 2 layers, hidden width tuned so it has ~similar params to the DenseNet arm but no feature concatenation; (2) a 'DenseNet-style' net with dense connections (each layer receives concatenation of all previous layer outputs within a block) at reduced width so that its total parameter count is deliberately smaller than the ResNet arm (mimicking the paper's core comparison of fewer params for equal/better accuracy). Both trained with plain SGD, no weight decay, no dropout, for 300 epochs full-batch on 80% train / 20% test split (1437 train / 360 test), so the small train set encourages a visible train/test gap. Both arms use identical initialization scheme, learning rate, and epoch budget; only the connectivity pattern (dense vs residual) and resulting width/param count differ, consistent with the paper's own comparison being at matched-or-fewer parameters for DenseNet.

**Why the claim should transfer.** The claimed effect rests on an architecture-level mechanism -- concatenative feature reuse (DenseNet) lets later layers access all earlier feature maps directly, so achieving a given representational capacity needs fewer new parameters per layer than residual summation (ResNet), which must relearn/carry features additively. This mechanism is not tied to convolution, image size, or depth in the hundreds of layers; it is a property of how layer outputs are combined and reused, which is preserved even in shallow fully-connected networks. By deliberately giving the dense-connectivity arm fewer parameters than the residual arm (matching the paper's own comparison regime) and by keeping the training set small enough that the shallow nets do not trivially reach near-zero test error (visible train/test gap), the reduced setup keeps the regime where 'more efficient information reuse' can plausibly translate into equal-or-better test accuracy despite fewer parameters. If dense connectivity's efficiency advantage is real and architecture-general, it should still let the smaller DenseNet-style arm match or beat the larger ResNet-style arm's test error under identical training budget; if the advantage only exists at deep-CNN scale, this experiment will correctly show no effect, which is itself informative.

**Seeds per arm:** 3 · **Estimated cost:** 50 min · **Code source:** from_scratch

**Changes from the paper**

- CIFAR-10/SVHN (32x32 RGB, 10-100 classes) -> sklearn 8x8 digits (10 classes) -- no network access is available; digits is the only bundled image-like dataset and still requires learning nonlinear features from pixels, preserving the qualitative image-classification setting.
- 300-epoch deep CNN (100-190 layers) -> 300-epoch shallow hand-rolled numpy MLP-with-skips (~6 layers) -- CPU-only budget of 60 minutes cannot fit deep conv nets; depth is shrunk uniformly for both arms so the relative comparison (dense vs residual connectivity at matched compute) is preserved.
- Convolutional layers -> fully-connected layers -- no DL framework (no autograd/conv ops) is available, only numpy; the mechanism under test (information reuse via concatenation vs summation across layers) is realizable with dense layers and does not require convolution to manifest.
- Data augmentation removed -- augmentation is orthogonal to the architectural parameter-efficiency claim being tested and would only add noise/compute at this scale.
- Batch SGD, no weight decay/dropout -- keeps the comparison isolated to the connectivity difference (invariant 3); regularizers are not part of this claim.
- Small train split (1437 examples) with no early stopping -- shrinks data enough that the shallow nets still show a nontrivial train/test gap (i.e. do not trivially reach ~0% test error), so parameter-efficiency differences between the two connectivity patterns have room to appear.

**Deliberately preserved**

- The core architectural distinction: dense (concatenative, feed-forward-to-all-later-layers) connections vs residual (additive, identity-shortcut) connections.
- Matched depth (number of layers) and matched training procedure/hyperparameters (optimizer, learning rate, epochs, initialization) between the two arms, so only connectivity/param-count differs.
- The comparison structure of the original claim: DenseNet arm is deliberately given fewer total parameters than the ResNet arm, mirroring Table 2's regime.
- Same train/test split, seeds, and evaluation metric (test error rate) for both arms.

### densenetbc_most_param_efficient_variant

> Among DenseNet variants (plain, DenseNet-C, DenseNet-B, DenseNet-BC), DenseNet-BC is consistently the most parameter-efficient in achieving low test error on CIFAR-10+.

Source: Sec. 5 (Model compactness); Figure 4 left panel · Metric: test error rate vs parameter count · Expected: DenseNet-BC parameter efficiency > DenseNet-B > DenseNet-C > plain DenseNet

**Verdict: Inconclusive**

treatment: 0.8937 (sd 0.0132, n=3); control: 0.903 (sd 0.0147, n=3). Effect in the predicted direction: +0.009333 [95% CI -0.008889, +0.027], Welch p=0.459. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect. The baseline arm never fit its own training data (training error 0.905), so this comparison is between two models that did not learn. The experiment needs redesigning, not more seeds.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** On CIFAR-10+ (with standard augmentation), the paper trains DenseNet variants (plain DenseNet, DenseNet-C with compression, DenseNet-B with bottleneck layers, and DenseNet-BC with both) at depths 100-250 and growth rates 12-40, then plots test error vs. parameter count (Fig. 4 left) to show DenseNet-BC achieves the lowest error for a given parameter budget, more efficiently than the other variants.

**Reduced setup.** Using sklearn's 8x8 digits dataset (1797 images, 10 classes) as a stand-in for CIFAR-10, implement a small hand-written numpy 'DenseNet-style' block architecture: a shallow densely-connected feature-concatenation network with 3 dense blocks of 4 layers each, growth rate k=4, operating on flattened/reshaped 8x8x1 inputs treated as a tiny 'image' via 3x3 conv-like linear filters (implemented in numpy as strided patch convolutions). Four variants are built with the same depth/growth-rate but differing structure: (1) plain -- each layer in a block takes only the concatenated output of the block so far, no bottleneck, no compression; (2) DenseNet-C -- adds a compression factor theta=0.5 at each transition (reduces feature maps between blocks) but no bottleneck; (3) DenseNet-B -- adds a 1x1 bottleneck (reduces channels before the 3x3 conv layer) but no compression; (4) DenseNet-BC -- both bottleneck and compression together. All four use only 300 training images (30/class) and are evaluated on 1000 held-out test images, trained for 40 epochs of full-batch gradient descent with a small learning rate, no data augmentation. For each variant we sweep 3 parameter budgets (achieved by varying growth rate k in {2,4,8}) to produce a parameter-count vs test-error curve.

**Why the claim should transfer.** The claim is fundamentally about a structural/architectural property: that reducing redundant parameters via bottlenecks and compression, while preserving dense connectivity's feature-reuse benefit, gives a better error-per-parameter tradeoff than not doing so. This mechanism does not depend on CIFAR's specific pixel statistics or on hundreds of layers -- it depends only on (a) there being genuine redundancy in concatenated feature maps for compression to exploit without losing information, and (b) there being enough input complexity that a small training set causes overfitting/inefficient parameter use in the plain variant, giving bottleneck/compression room to show a benefit. With only 300 training images (30/class) and a modestly expressive 3-block network, the plain variant should show a visible train/test gap (it has enough capacient depth via concatenation to memorize 300 examples but generalize worse), giving room for compression and bottlenecks to reduce overfitting-inducing parameters while retaining accuracy -- exactly the regime the original claim describes at CIFAR scale. If DenseNet-BC's error-vs-parameter curve does not lie below the others' in this reduced regime, that is genuine evidence against generality of the mechanism, not just an artifact of scale, because the qualitative structural comparison (concatenation + bottleneck + compression vs. subsets thereof) is preserved exactly, only the size of everything is uniformly shrunk.

**Seeds per arm:** 3 · **Estimated cost:** 55 min · **Code source:** from_scratch

**Changes from the paper**

- CIFAR-10 -> sklearn 8x8 digits (1797 images) -- CIFAR is unavailable with no network access; digits is the closest small-image analogue with multi-class structure and enough visual redundancy for a densely-connected conv-like architecture to exploit, preserving the core mechanism (feature reuse via concatenation) the claim is about.
- Depth/growth-rate reduced from 100-250 layers / k=12-40 to 3 blocks x 4 layers / k in {2,4,8} -- the claim is about the *relative ordering* of parameter efficiency across variants, which is a structural property of concatenation + bottleneck + compression, not a property that requires hundreds of layers; small-depth networks still have blocks and transitions that bottleneck/compression can act on.
- Training set restricted to 300 images (30/class), no augmentation -- a small training set forces a visible train/test gap in the baseline (plain) variant, which is required for parameter-efficiency effects (compression, bottleneck) to visibly change the error/parameter tradeoff; using all 1797 images with a network this small would let all variants fit near-perfectly and hide differences.
- Full-batch gradient descent for 40 epochs replacing SGD with momentum on CIFAR for 300 epochs -- purely a compute-budget reduction; convergence behavior of the relative ranking of variants under gradient descent should not depend on the specific optimizer variant used, only that all four architectures are trained to a comparable degree of convergence under identical optimization settings.
- Numpy from-scratch implementation replacing the official PyTorch/Lua-Torch repo -- no deep learning framework is installed in the sandbox (only numpy/scikit-learn), so the architecture (dense blocks, concatenation, 1x1 bottleneck, transition compression) is reimplemented by hand at small scale, preserving the same connectivity pattern and parameter-reduction mechanisms as the original code.
- Parameter sweep via growth rate k in {2,4,8} instead of paper's k in {12,24,40} and depths 100-250 -- three points at small scale suffice to trace an error-vs-parameter-count curve per variant, enough to check whether BC's curve lies below B's, which lies below C's, which lies below plain's, mirroring Fig. 4's comparison logic without needing the full range.

**Deliberately preserved**

- The four-way architectural distinction: presence/absence of 1x1 bottleneck layers (the 'B' in BC) and presence/absence of compression at transitions (the 'C' in BC), applied identically across all variants except for these two structural toggles.
- Dense connectivity within blocks (each layer receives the concatenation of all previous layer outputs within its block), which is the core DenseNet mechanism the paper's efficiency claim depends on.
- Identical training data, training length, optimizer, learning rate, and number of seeds across all four variants -- only the architectural toggles differ, respecting invariant 1.
- Evaluation via test error rate plotted/tabulated against total parameter count per variant, matching the paper's own metric and comparison structure (Fig. 4 left panel).

## Claims not tested

- **`densenet_bc_sota_cifar`** (absolute) — DenseNet-BC with 190 layers and growth rate 40 achieves lower error than prior state-of-the-art (including wide ResNet) on CIFAR-10+ and CIFAR-100+. _This is an absolute headline-number claim comparing specific error rates to prior state-of-the-art, which cannot be validated by construction at reduced scale._
- **`densenetbc_matches_resnet1001_fewer_params`** (comparative) — A 100-layer DenseNet-BC with growth rate 12 (0.8M params) achieves comparable accuracy to a 1001-layer pre-activation ResNet (10.2M params) on CIFAR-10+ and CIFAR-100+, using about 90% fewer parameters. _One arm requires a 1001-layer ResNet, which is far beyond a 60-minute CPU-only budget to train even a handful of seeds._
- **`capacity_scaling_trend`** (scaling_trend) — Without compression or bottlenecks, DenseNet accuracy on CIFAR-10+/100+ improves consistently as depth L and growth rate k increase, indicating the model exploits increased capacity without overfitting. _This is explicitly a scaling trend claim about increasing depth and growth rate, whose validity depends on capacity/scale and is excluded by the scale-dependence rule._
- **`densenet_less_overfitting_no_augmentation`** (comparative) — On datasets without data augmentation (C10, C100), DenseNets show much larger relative error reductions over prior work than on augmented datasets, suggesting DenseNets are less prone to overfitting. _This compares relative error reduction with vs without augmentation using small comparable DenseNet/baseline models on a CIFAR subset, a direction plausibly driven by architecture rather than scale._
- **`densenet201_matches_resnet101_fewer_params`** (comparative) — On ImageNet, DenseNet-201 with about 20M parameters achieves validation error similar to a 101-layer ResNet with more than 40M parameters. _Requires full ImageNet-scale pretraining of DenseNet-201 and ResNet-101, which is far over any CPU-only 60-minute budget._
- **`densenet_flops_efficiency_imagenet`** (comparative) — A DenseNet requiring computation comparable to ResNet-50 achieves accuracy on par with ResNet-101, which needs about twice the FLOPs. _Depends on ImageNet-scale training and large pretrained models, not reproducible on a small CPU budget._
- **`densenetbc_third_params_of_resnet`** (comparative) — To reach the same accuracy level on CIFAR-10+, DenseNet-BC needs only about one third of the parameters required by comparable pre-activation ResNets. _A scaled-down comparison of DenseNet-BC vs pre-activation ResNet parameter counts at matched accuracy on a small CIFAR subset can plausibly preserve the qualitative parameter-efficiency gap._
- **`svhn_250layer_no_improvement`** (ablation) — On SVHN, increasing DenseNet-BC depth to 250 layers does not further reduce error compared to a shallower DenseNet, likely due to overfitting on this easier task. _Training a 250-layer DenseNet-BC is computationally infeasible within a 60-minute CPU-only budget even at reduced dataset size._

## How these experiments were run

> **These results were produced without container isolation.** The experiments ran in a restricted subprocess, with network access blocked and resources capped, but not inside a sandbox that can contain what it runs. Treat the results as a demonstration of the pipeline rather than as a trustworthy measurement, and re-run under Docker before relying on them.

## Limitations

Read these results narrowly.

- **A negative result here does not refute the paper.** These experiments run at a fraction of the
  original scale. An effect that disappears when the model, the data, or the training budget shrinks
  may still be real at full scale; that is precisely what reduced-scale testing cannot tell us.
- **A positive result is not a reproduction.** It says the direction of the claim survived
  shrinking, not that the paper's numbers were reproduced.
- **Seed counts are small.** With a handful of seeds per arm, statistical power is low. An
  inconclusive verdict usually means there was not enough evidence either way, not that the effect
  is absent.
- **Absolute claims are never testable this way** and are recorded without being run.
- The reduced experiments were written from the paper's description, so they may differ from the
  authors' implementation in ways that matter.
