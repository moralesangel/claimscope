## Tested claims

### maml_beats_pretrain_sinusoid

> MAML fine-tuned on a few datapoints adapts to new sinusoid tasks much better than a model pretrained on all tasks and then fine-tuned, especially avoiding catastrophic overfitting.

Source: Fig. 2, Fig. 3 · Metric: mean-squared error · Expected: MAML > pretraining_baseline

**Verdict: Inconclusive**

MAML: 4.057 (sd 1.31, n=3); pretraining_baseline: 4.05 (sd 1.31, n=3). Effect in the predicted direction: -0.007597 [95% CI -1.744, +1.728], Welch p=0.995. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect. The baseline arm never fit its own training data (training error 3.109), so this comparison is between two models that did not learn. The experiment needs redesigning, not more seeds.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** MAML is trained via meta-learning on a distribution of sinusoid regression tasks (amplitude and phase varying), then fine-tuned on K=5-10 datapoints from a new sinusoid task with a few gradient steps. This is compared to a network pretrained by joint training on all tasks (standard multi-task regression), then fine-tuned on the same K points. Figure 2/3 show MAML achieves much lower MSE after fine-tuning and does not catastrophically overfit, while the pretrained baseline overfits badly on the few adaptation points.

**Reduced setup.** Synthetic sinusoid regression, generated in numpy (no real dataset needed -- this is inherently synthetic, so no substitution table entry is needed for a benchmark). Tasks: y = A*sin(x+phase), A ~ U[0.1,5.0], phase ~ U[0,pi], x ~ U[-5,5]. Model: 1-hidden-layer MLP with 40 hidden units, tanh activation, implemented by hand in numpy with manual forward/backward (since no DL framework is available). MAML arm: meta-train over 200 sampled tasks, each with an inner loop of 1 gradient step (lr=0.01) on K=10 support points, outer update via first-order MAML (foMAML, avoiding second-order tensors) with meta-lr=0.001, for 500 meta-iterations. Pretrain arm: same architecture and total compute -- train jointly on the aggregate loss over the same 200 tasks x same number of gradient steps (500 iterations x batch of tasks), i.e. standard multi-task SGD pretraining, no meta-gradient. Evaluation: for 20 new held-out tasks, fine-tune each arm's final weights with K=5 support points using 1-5 gradient steps (lr=0.01), measure MSE on 50 held-out query points from the same task. Report mean test MSE across tasks and steps, and also report post-fine-tuning training-support MSE to check for catastrophic overfitting (support MSE ~0 but query MSE blowing up in the baseline).

**Why the claim should transfer.** The claimed effect rests on a simple mechanism: MAML's outer loop explicitly optimizes for good post-few-step performance, producing an initialization near a "sensitive" region of weight space from which 1-5 gradient steps on very few points generalize well, whereas jointly pretrained weights are optimized for average performance across all tasks and have no incentive to be adaptable -- when fine-tuned on just K=5-10 points they overfit those points and lose accuracy on held-out query points from the same task. This mechanism does not depend on network depth, on using exact second-order MAML gradients, or on training for tens of thousands of iterations; it only requires (a) enough task diversity that no single fixed function fits all tasks, (b) genuinely few adaptation points relative to model capacity so overfitting is possible for the baseline, and (c) enough meta-training iterations for the MAML inner-loop structure to start specializing. All three conditions are preserved: task diversity (amplitude/phase ranges matching the paper), K=5-10 fine-tuning points against a 40-unit hidden layer that can easily overfit 5-10 points, and 500 meta-iterations over 200 resampled tasks, which is enough for foMAML's inner-loop mechanism to differentiate from pure joint training on this low-dimensional problem. Because both arms share the same architecture, same number of tasks, same iteration count and same evaluation protocol, any observed MSE gap must come from the meta-learning mechanism itself and not from confounds, making the sign of the gap (MAML < pretrain-then-finetune MSE, especially at query points after few steps) informative about the paper's direction.

**Seeds per arm:** 3 · **Estimated cost:** 45 min · **Code source:** from_scratch

**Changes from the paper**

- Use first-order MAML (foMAML) instead of full second-order MAML -- justified because computing second derivatives by hand in numpy is expensive and error-prone; foMAML is a documented, commonly-used approximation in the original paper's own ablations that preserves the qualitative meta-learning behavior (fast adaptation without overfitting), so it should not flip the direction of the effect.
- Small 1-hidden-layer, 40-unit MLP instead of the paper's 2-hidden-layer, 40-unit MLP -- justified because the mechanism (few-shot adaptation vs. joint pretraining overfitting on K points) does not depend on network depth; a single hidden layer is already flexible enough to fit sinusoids and to overfit on 5 points, so the qualitative gap should still appear.
- 500 meta-iterations / 500 pretraining iterations over 200 tasks instead of tens of thousands of iterations over an effectively infinite task distribution -- justified by CPU time budget; both arms get identical task counts, batch sizes, and iteration counts, preserving invariant 1 (equal budget), and 200 tasks with resampling is enough to see joint pretraining smooth over task identity while MAML's inner-loop structure specializes on the fly.
- K=5-10 support points fixed, matching the paper's low-data adaptation regime -- kept, not changed, but noted since it is central to inducing catastrophic overfitting.
- Deterministic sinusoid generator implemented from scratch in numpy rather than any package dataset -- justified because the claim's data (sinusoid tasks) is inherently synthetic and has no benchmark substitute needed; sklearn's built-in datasets are irrelevant here since this task is procedurally generated regression, not a fixed benchmark.

**Deliberately preserved**

- The core algorithmic contrast: gradient-based meta-learning (inner+outer loop, MAML-style) vs. joint pretraining followed by fine-tuning on the same architecture -- this is exactly what the claim is about.
- The few-shot (K=5-10 points) fine-tuning regime, which is what induces catastrophic overfitting in the pretrained baseline and is the crux of the claim.
- Same base architecture (single hidden-layer MLP, same width) and same optimizer (plain SGD) for both arms.
- Same number of tasks, same batch sizes, same number of training iterations and same number of fine-tuning gradient steps at evaluation time for both arms, satisfying invariant 1.
- Same held-out evaluation tasks and same K for fine-tuning in the final comparison for both arms.

### maml_improves_with_more_gradient_steps_sinusoid

> A model trained with MAML continues to reduce test-time regression loss with additional gradient steps at meta-test time, despite being optimized for only one gradient step during meta-training.

Source: Fig. 3, Sec. 5.1 · Metric: mean-squared error · Expected: loss decreases with more gradient steps

**Verdict: Inconclusive**

treatment: 4.794 (sd 0.956, n=5); control: 4.473 (sd 0.935, n=5). Effect in the predicted direction: -0.3207 [95% CI -1.346, +0.7171], Welch p=0.606. The baseline arm never fit its own training data (training error 4.205), so this comparison is between two models that did not learn. The experiment needs redesigning, not more seeds.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** MAML is meta-trained on a distribution of sinusoid regression tasks (amplitude in [0.1,5.0], phase in [0,pi]) using a small MLP, with only one inner gradient step used during meta-training. At meta-test time, the paper shows that taking additional gradient steps (more than the one used in training) on a new sinusoid task continues to reduce MSE on held-out points, Fig. 3.

**Reduced setup.** Synthetic sinusoid regression task distribution generated directly in numpy (no dataset substitution needed, since this is already a synthetic-data claim): tasks are y = A*sin(x+phi), A in [0.1,5.0], phi in [0,pi], x in [-5,5]. Model: 2-hidden-layer MLP, width 40, tanh activations, implemented by hand in numpy with manual forward/backward pass (small enough for autograd-free backprop). Meta-training: 200 meta-iterations, meta-batch of 10 tasks per iteration, 10 points per task for inner-loop adaptation, 1 inner gradient step per meta-training iteration (matching paper), outer-loop update via first-order MAML (skip second-order term to keep numpy implementation tractable). At meta-test time, sample 20 new tasks, adapt with up to 10 gradient steps (evaluate MSE on 10 held-out query points after 0,1,2,...,10 steps), and report how MSE changes with step count. Single arm: MAML only, no comparison model needed since claim is single-arm within-model trend.

**Why the claim should transfer.** The claim is about a structural/geometric property of MAML: meta-training for 1 step finds an initialization from which the loss surface, locally around that point, continues to decrease along the gradient direction for several more steps because MAML's outer objective only ever evaluates and backpropagates through a 1-step-adapted point but does not penalize (or benefit from) taking additional steps, so nothing during training discourages further descent -- the initialization is simply "good and steerable," not "already optimal after exactly one step." This property does not depend on network scale, dataset scale, or the number of meta-training iterations being large; it depends only on there being (a) a task family simple enough that gradient descent on a handful of points meaningfully reduces regression error, and (b) enough meta-training for the initialization to be nontrivially shaped (not random). A 2x40 MLP meta-trained for 200 iterations on 10-task batches is enough to move well away from a random initialization and produce a discernibly task-adapted starting point (baseline train/test regression error will show clear reduction from step 0 to step 1, confirming the model is in the 'meta-learning is working' regime), while still leaving room for further loss reduction at steps 2-10 because 200 iterations with first-order MAML is unlikely to produce a degenerate fixed point that already sits in a local minimum after 1 step. If, empirically, MSE decreased from step 0 to 1 but then increased or plateaued immediately at step 2, that would be a genuine (if weak) signal against transfer; the small-scale setup keeps this failure mode visible and is not designed to force the outcome.

**Seeds per arm:** 5 · **Estimated cost:** 45 min · **Code source:** from_scratch

**Changes from the paper**

- Use first-order MAML (omit second-order gradient-through-gradient term) -- this only changes the meta-training signal quality, not the qualitative fact that more inner steps at test time should keep reducing loss on a well-adapted MLP; the paper's own ablations show first-order MAML performs comparably.
- Reduce network to 2x40 tanh MLP from the paper's 2x40 ReLU (or similar) -- width/depth already matches paper's small MLP; only difference is activation, chosen for smooth analytic gradients in a hand-written numpy backprop, which does not change the direction of the effect (more adaptation steps reduce loss on a differentiable regression task).
- Reduce meta-training iterations to 200 and meta-batch size to 10 tasks (from paper's tens of thousands of iterations and larger batches) -- meta-training only needs to reach a 'good but not perfect after 1 step' initialization; the claim is about what happens after that initialization is meta-trained for 1 step, and even partial meta-training produces initializations from which further gradient steps continue to help, since the phenomenon is about the shape of the loss landscape around a 1-step-tuned init, not about full convergence.
- Test-time adaptation grid reduced to 10 steps (paper sometimes shows up to 10+ steps) and 20 test tasks -- sufficient points to see a monotonic-decreasing or plateauing trend without excessive compute.
- Use 10 inner-loop points and 10 query points per task (smaller than some paper variants with more shots) -- keeps compute low while preserving the core regression-task structure (K-shot adaptation, held-out query evaluation) that the claim depends on.

**Deliberately preserved**

- The exact functional form of the task distribution (sinusoids with varying amplitude and phase) that defines the sinusoid regression benchmark.
- The MAML algorithm itself: meta-training with exactly 1 inner gradient step, and testing generalization to more steps than trained on.
- The architecture class (small feed-forward MLP with tanh/ReLU-style nonlinearities), not swapped for a different model family.
- The core measurement: MSE on held-out query points as a function of number of test-time gradient steps, which is exactly what Fig. 3 in the paper plots.

## Claims not tested

- **`maml_omniglot_sota`** (comparative) — MAML achieves accuracy on 5-way and 20-way Omniglot classification (1-shot and 5-shot) that matches or slightly exceeds prior state-of-the-art methods such as Siamese networks, matching networks, neural statistician, and memory modules. _Comparing against absolute reported numbers from several prior state-of-the-art methods (Siamese, matching nets, neural statistician, memory module) is effectively an absolute-number comparison and those baselines are not easily reproducible from scratch within a CPU budget._
- **`maml_beats_mann_omniglot`** (comparative) — MAML with a non-convolutional network substantially outperforms memory-augmented neural networks (MANN) on 5-way 1-shot and 5-shot Omniglot classification. _Both MAML and MANN can be implemented with small non-convolutional networks on a reduced Omniglot subset within CPU budget, and the comparative direction (MAML > MANN) is an architecture/algorithm effect not tied to scale._
- **`maml_beats_baselines_miniimagenet`** (comparative) — MAML outperforms fine-tuning baseline, nearest neighbor baseline, matching networks, and meta-learner LSTM on 5-way 1-shot and 5-shot MiniImagenet classification. _MiniImagenet-based few-shot comparisons against multiple baselines (matching nets, meta-learner LSTM) require nontrivial image data and training pipelines that exceed a 60-minute CPU-only budget for 3-seed multi-arm runs._
- **`first_order_approx_comparable_to_full_maml`** (ablation) — A first-order approximation of MAML that omits second derivatives achieves nearly the same accuracy as full MAML on MiniImagenet classification while being about 33% faster. _This relies on MiniImagenet-scale image classification training, which is too costly to reproduce for both arms with multiple seeds under a CPU-only 60-minute budget._
- **`maml_faster_rl_adaptation_2d_navigation`** (comparative) — In the 2D navigation RL task, MAML adapts to new goal positions much faster than pretraining or random initialization, and continues to improve with additional gradient updates. _The 2D navigation RL task is a tiny synthetic environment where MAML, pretraining, and random-init policies can each be trained cheaply on CPU, and the relative speed-of-adaptation ordering is a structural effect likely to transfer._
- **`maml_faster_rl_adaptation_locomotion`** (comparative) — On high-dimensional locomotion tasks (half-cheetah and ant), MAML adapts to new goal velocities/directions substantially faster than conventional pretraining or random initialization, reaching good performance within two or three gradient steps. _High-dimensional locomotion tasks (half-cheetah, ant) require MuJoCo-based RL training that is too compute-intensive to fit a 60-minute CPU-only budget across three arms and seeds._
- **`pretraining_worse_than_random_init_rl`** (comparative) — In some locomotion RL tasks, pretraining as an initialization performs worse than random initialization. _This claim is tied to the same high-dimensional locomotion RL setup as above, which is infeasible to reproduce on CPU within the time budget._
- **`multitask_param_averaging_worse_than_pretrain`** (comparative) — Averaging parameters across separately-trained single-task regressors (multi-task parameter averaging) performs worse than pretraining on all tasks jointly, and much worse than MAML, on 5-shot sinusoid regression. _All three arms (MAML, pretrain-on-all-tasks, multi-task parameter averaging) are simple to run on synthetic sinusoid regression with small networks, and the ordering reflects an optimization/algorithmic effect expected to hold at reduced scale._

## How these experiments were run

> **These results were produced without container isolation.** The experiments ran in a restricted subprocess, with network access blocked and resources capped, but not inside a sandbox that can contain what it runs. Treat the results as a demonstration of the pipeline rather than as a trustworthy measurement, and re-run under Docker before relying on them.

## Limitations

Read these results narrowly.

- **A negative result here does not refute the paper.** These experiments run at a fraction of the
  original scale. An effect that disappears when the model, the data, or the training budget shrinks
  may still be real at full scale; that is precisely what reduced-scale testing cannot tell us.
- **A positive result is not a reproduction.** It says the direction of the claim survived
  shrinking, not that the paper's numbers were reproduced.
- **Seed counts are small.** With a handful of seeds per arm, statistical power is low. An
  inconclusive verdict usually means there was not enough evidence either way, not that the effect
  is absent.
- **Absolute claims are never testable this way** and are recorded without being run.
- The reduced experiments were written from the paper's description, so they may differ from the
  authors' implementation in ways that matter.
