## Tested claims

### dynamic_masking_vs_static

> Dynamic masking, which regenerates the mask pattern each time a sequence is fed to the model, performs comparably to or slightly better than the original static masking approach used in BERT.

Source: Table 1 · Metric: F1 / accuracy on SQuAD2.0, MNLI-m, SST-2 · Expected: dynamic_masking >= static_masking

**Verdict: Inconclusive**

dynamic_masking: 0.1317 (sd 0.0161, n=3); static_masking: 0.1317 (sd 0.0161, n=3). Effect in the predicted direction: +0 [95% CI -0.02, +0.02], Welch p=1. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect. The baseline arm never fit its own training data (training error 0.823), so this comparison is between two models that did not learn. The experiment needs redesigning, not more seeds.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** RoBERTa paper compares static masking (mask pattern fixed once at data preprocessing, reused every epoch) vs dynamic masking (mask pattern regenerated each time a sequence is fed to the model during training) for BERT-style masked language model pretraining, then fine-tunes on SQuAD2.0, MNLI-m, and SST-2, evaluating F1/accuracy on large transformer models trained on the BookCorpus+Wikipedia over many epochs.

**Reduced setup.** No PyTorch/network available, so no fairseq/BERT can be run. Instead, replicate the *mechanism* the claim is about -- whether regenerating a stochastic masking/corruption pattern each time a sample is seen (vs. fixing it once and reusing it every epoch) improves generalization -- using a numpy-only masked-reconstruction-style denoising autoencoder-classifier pretext task on sklearn's 8x8 digits (1797 images, 64 features) standing in for MNIST/BERT's token corpus. Concretely: (1) pretraining phase -- for each of 300 training images, apply a random binary "mask" that zeroes out 30% of the 64 pixel features (analogous to token masking), train a small 1-hidden-layer numpy MLP (64->32->64) via mean-squared reconstruction loss with plain SGD for 40 epochs; static arm generates one mask per image ONCE before training and reuses it every epoch, dynamic arm regenerates a fresh random mask for each image every epoch. (2) fine-tuning phase -- freeze the 64->32 encoder, train a small linear softmax head (32->10) on top of the pretrained representation using 300 labeled training images for 40 epochs, then evaluate classification accuracy on a held-out test set of 200 images (digits 0-9). Both arms use identical architecture, identical optimizer, identical number of epochs, identical train/test split, identical labeled data; the only difference is whether the mask pattern is drawn once (static) or fresh each epoch (dynamic).

**Why the claim should transfer.** The claim is fundamentally about whether resampling a stochastic corruption pattern each time a sample is seen acts as a better (or at least equal) regularizer than fixing that pattern once and reusing it repeatedly -- a property of the masking *procedure* itself, not of transformers, text, or scale. With only 300 labeled training images and a moderately capacious 64->32->64 autoencoder trained for 40 epochs, the static arm's fixed masks let the small model partially learn to "expect" which specific pixels will be missing for each specific training image (memorizing a mask-conditioned reconstruction shortcut), producing a visible train/test reconstruction and downstream-accuracy gap; the dynamic arm's fresh masks each epoch prevent this shortcut and instead force the encoder to learn representations robust to any masking, which should yield equal or better downstream test accuracy. This mirrors the argument RoBERTa's authors make for why dynamic masking works: it exposes the model to a greater diversity of corruption patterns per example over training, acting as implicit data augmentation. Because this mechanism does not depend on transformer architecture or language, and because the reduced setup is explicitly pushed into a regime with a visible train/test gap for the baseline (static) arm, the direction of the effect (dynamic >= static) has a reasonable chance to transfer, though the absolute margin may differ substantially in magnitude and cannot be assumed to be quantitatively similar to the paper's numbers.

**Seeds per arm:** 3 · **Estimated cost:** 12 min · **Code source:** from_scratch

**Changes from the paper**

- Replace fairseq/BERT masked-language-model pretraining on BookCorpus+Wikipedia with a numpy MLP masked-pixel-reconstruction pretext task on load_digits -- justified because the claim is about the *mechanism* of static vs. dynamic mask regeneration, not about transformers or text specifically; masking-schedule effects (does reusing a fixed corruption pattern let the model overfit to which positions are masked, vs. dynamic masking acting as a stronger regularizer) are architecture-agnostic and should transfer to a small denoising autoencoder.
- Replace SQuAD2.0/MNLI-m/SST-2 fine-tuning with a small 10-class digit classification fine-tuning head -- justified because these downstream tasks only serve to measure how well the pretrained representation generalizes; a labeled classification task with a train/test gap plays the same functional role.
- Use only 300 labeled training images (out of 1797) so the small MLP encoder can memorize per-pixel mask locations in the static arm, creating a visible train/test gap for the reconstruction+classification pipeline to have room to be affected by mask regeneration -- justified because with the full 1797 images and few epochs the model would underfit and neither masking strategy could show an effect.
- Reduce model size to a single hidden layer 64->32->64 autoencoder and 32->10 linear head, trained via plain SGD for 40 epochs -- justified because the direction of the static-vs-dynamic masking effect depends on whether the corruption pattern is fixed or resampled, not on model depth/width; a small model keeps runtime within the CPU budget while still being able to overfit the fixed mask in the static arm.
- Run 3 seeds per arm instead of paper's typical single large run -- justified because seed variance must be characterized to claim a comparable-or-better direction reliably at this small scale.

**Deliberately preserved**

- The core mechanism: one arm fixes the random corruption/mask pattern once before training and reuses it every epoch (static), the other resamples the pattern fresh every time a sample is presented (dynamic) -- this is exactly the manipulation the claim is about.
- Architecture and hyperparameters (encoder size, decoder size, classifier head size, optimizer, learning rate, epoch count) identical across both arms.
- Identical train/test split and identical amount of labeled data available for fine-tuning across both arms.
- A masked-reconstruction pretraining -> fine-tuning pipeline structurally analogous to BERT's masked-LM-pretrain-then-finetune paradigm.

### nsp_removal_no_hurt

> Removing the Next Sentence Prediction (NSP) loss and training on contiguous full sentences does not hurt, and can slightly improve, downstream task performance, contradicting the original BERT paper's claim that NSP is necessary.

Source: Table 2 · Metric: F1 / accuracy on SQuAD, MNLI-m, SST-2, RACE · Expected: performance without NSP >= performance with NSP

**Verdict: Consistent at reduced scale**

full_sentences_no_nsp: 0.3938 (sd 0.0116, n=3); segment_pair_with_nsp: 0.3778 (sd 0.00666, n=3). Effect in the predicted direction: +0.01595 [95% CI +0.003359, +0.02687], Welch p=0.126. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** RoBERTa/BERT-style ablation: pretrain BERT-base (12 layers, 768 hidden) on BookCorpus+Wikipedia (~16GB text) with either (a) SEGMENT-PAIR+NSP inputs (two segments, binary NSP loss) or (b) FULL-SENTENCES with no NSP loss (contiguous sentences packed to max length, no NSP head), for hundreds of thousands of steps, then fine-tune and evaluate on SQuAD, MNLI-m, SST-2, and RACE.

**Reduced setup.** Since no text corpus, tokenizer, or deep learning framework is available (no network, only numpy/scikit-learn), the pretraining-objective mechanism cannot literally be tested on text. I substitute a synthetic analogue that preserves the *structural* comparison the claim is about: a masked/contiguous-representation-learning objective with vs. without an auxiliary 'pair relationship' prediction loss, on sklearn's 8x8 digits (1797 images, standing in for the pretraining corpus) using a from-scratch numpy MLP autoencoder-style model. Concretely: build a small numpy MLP encoder (64->32->16) trained with a reconstruction (masked-pixel-prediction, analogous to MLM) loss on 'contiguous' full images (arm A: full_sentences_no_nsp) versus the same encoder trained with the same reconstruction loss PLUS an auxiliary binary 'pair-order' classification loss on artificially constructed (real-pair vs shuffled-pair) concatenated image pairs (arm B: segment_pair_with_nsp), mirroring BERT's NSP construction (real next segment vs random segment). After 'pretraining' (200 gradient steps, batch 32, on 1400 train images), freeze the encoder and fine-tune a linear probe (logistic regression via sklearn) on a downstream 10-class digit classification task using only 200 labeled images (small, to induce a visible train/test gap so any degradation/help from NSP-style loss is visible), evaluating held-out accuracy on 397 test images. This is the closest honest analogue reachable with the available tools; it tests the direction of the claim (auxiliary pair-order loss does not help, and may hurt, representation quality for downstream fine-tuning) rather than the literal NSP/BERT claim.

**Why the claim should transfer.** The claim's mechanism, as argued in the original paper, is that NSP is an easy auxiliary task that does not encourage the encoder to learn representations useful for downstream single-segment/token-level tasks, and may even trade off capacity or introduce noisy training signal that harms the primary (MLM) representation quality. This is a claim about auxiliary-task interference during representation learning, which is architecture- and modality-agnostic: it should manifest whenever (a) the encoder is shared, (b) the downstream task depends on the primary (reconstruction) representation rather than the auxiliary pairwise task, and (c) there is limited labeled data so the downstream probe is sensitive to representation quality rather than saturating at near-100% regardless of encoder. My reduced setup keeps all three conditions: identical shared MLP encoder, downstream probe trained on the primary reconstruction/encoding output only, and a small labeled set (200/1797 images) chosen specifically so a train/test gap exists in the baseline (i.e., the probe does not trivially achieve ceiling accuracy), leaving room for a several-percentage-point difference between arms to appear. If the auxiliary pair-order loss genuinely competes for encoder capacity or introduces label noise unrelated to the reconstruction objective, the no-auxiliary-loss arm should match or exceed the with-auxiliary-loss arm even at this toy scale -- exactly the direction the claim predicts. The main risk to transfer is that a 3-layer MLP has much less capacity to notice interference than a 12-layer transformer, so a weak effect could be undetectable within noise across 3 seeds; I flag this as the key limitation but the sign of the comparison is still the best obtainable evidence at this budget.

**Seeds per arm:** 3 · **Estimated cost:** 25 min · **Code source:** from_scratch

**Changes from the paper**

- Replace BookCorpus+Wikipedia text pretraining with sklearn 8x8 digit images (1797 samples) -- no network access, no text data or tokenizer available; the claim is about whether an auxiliary same-input-different-loss objective helps or hurts downstream transfer, a structural question that survives a change of input modality.
- Replace BERT-base (12-layer transformer) with a small numpy MLP encoder (64-32-16 units) -- no PyTorch/TensorFlow/JAX available; a compact feed-forward encoder trained with backprop-by-hand preserves the essential comparison (shared encoder architecture, only the auxiliary loss differs between arms), satisfying invariant 3 (same architecture in both arms).
- Replace NSP's 'next sentence vs random sentence' binary classification with a synthetic 'real adjacent pair vs shuffled pair' binary classification built from concatenated image features -- this is the closest constructible analogue of NSP's segment-pair/random-pair mechanism given only tabular image data, and keeps the essential property NSP is criticized for: an auxiliary task added on top of the same representation-learning loss.
- Replace SQuAD/MNLI/SST-2/RACE fine-tuning with a linear-probe logistic regression classifier for 10-class digit recognition on a small labeled subset (200 train images) -- downsized to fit CPU/time budget while keeping a genuine train/test generalization gap so encoder quality differences are detectable.
- Reduce pretraining steps from hundreds of thousands to 200 gradient steps and reduce corpus size from 16GB to 1400 images -- necessary for a CPU budget of 60 minutes; the comparison is relative (arm A vs arm B under identical steps/data), so absolute undertraining should not differentially favor either arm.
- Use 3 seeds per arm (differing weight initialization and shuffle/probe splits) instead of the paper's single large run -- required by invariant 2, and variance across seeds lets us assess whether any observed direction is robust rather than noise.

**Deliberately preserved**

- The core comparison structure: identical encoder architecture and reconstruction/MLM-style loss in both arms, with the only difference being presence/absence of an auxiliary pairwise ordering loss (analogous to NSP) -- this isolates the variable the claim is about.
- Identical dataset, data splits, number of pretraining steps, batch size, and fine-tuning/probe procedure across both arms -- satisfies invariant 1 (equal budget/dataset/reduction/seeds).
- A downstream evaluation with a limited labeled fine-tuning set, preserving a genuine train/test generalization gap so representation quality differences can actually manifest in probe accuracy.
- 3+ seeds per arm with fixed random seeds for initialization and data shuffling, enabling a variance-aware comparison of the two arms' downstream accuracy.

## Claims not tested

- **`sentence_pair_hurts_performance`** (comparative) — Using single natural sentences per input segment (SENTENCE-PAIR) instead of multi-sentence segments hurts downstream task performance compared to the original segment-pair format, likely because the model cannot learn long-range dependencies. _This ablation compares two input-formatting schemes on the same small model and corpus, so the directional effect of losing long-range context should be observable at reduced scale._
- **`doc_sentences_beats_full_sentences`** (comparative) — Restricting input sequences to come from a single document (DOC-SENTENCES) performs slightly better than allowing sequences to span multiple documents (FULL-SENTENCES). _This is a comparable-arm ablation on document-boundary handling during pretraining that can be run cheaply on a small corpus while likely preserving the direction of the effect._
- **`large_batch_improves_perplexity_and_accuracy`** (scaling_trend) — Training BERT-base with larger mini-batches (2K or 8K sequences), while controlling for total computational cost, improves both masked language model perplexity and downstream task accuracy compared to the original batch size of 256. _This is a scaling_trend claim about batch size effects controlled for total compute across very large batches (2K-8K), which requires substantial compute per arm and the effect is tied to large-batch training dynamics that may not hold at CPU-only reduced scale._
- **`roberta_scales_with_data_and_steps`** (scaling_trend) — RoBERTa's downstream task performance (SQuAD, MNLI-m, SST-2) continues to improve as pretraining data is increased from 16GB to 160GB and as the number of pretraining steps is increased from 100K to 300K to 500K. _This is an explicit scaling_trend claim across large data sizes (16GB-160GB) and many training steps (100K-500K), which cannot fit a 60-minute CPU-only budget and the effect is defined by scale itself._
- **`roberta_beats_bertlarge_and_xlnet_controlled`** (comparative) — When controlling for training data and architecture, RoBERTa substantially outperforms the originally reported BERTLARGE results, and after longer training it also outperforms XLNetLARGE on most tasks. _Not assessed: the model did not return a decision for this claim, so it was skipped. This is a gap in the triage output, not a judgement that the claim is untestable._
- **`roberta_sota_glue_dev`** (comparative) — RoBERTa achieves state-of-the-art results on all 9 GLUE development set tasks in the single-task setting, outperforming both BERTLARGE and XLNetLARGE. _This claim depends on large pretrained models (RoBERTa, BERTLARGE, XLNetLARGE) whose absolute state-of-the-art comparison cannot be reproduced at small scale or within the compute budget._
- **`roberta_glue_leaderboard_sota`** (absolute) — RoBERTa achieves state-of-the-art results on 4 of 9 GLUE tasks and the highest average score on the public GLUE leaderboard, without relying on multi-task finetuning, matching a score of 88.5 versus XLNet's 88.4. _This is an absolute headline-number claim (88.5 vs 88.4 on the GLUE leaderboard) which by definition cannot be tested at reduced scale._
- **`roberta_sota_squad_and_race`** (comparative) — RoBERTa sets a new state-of-the-art on SQuAD 2.0 development set (improving over XLNet by 0.4 EM and 0.6 F1) and achieves state-of-the-art accuracy on the RACE test set, without using additional training data. _This claim compares specific state-of-the-art numbers against XLNetLARGE on large benchmarks, requiring large-scale pretrained models that are not reproducible within a CPU-only 60-minute budget._

## How these experiments were run

> **These results were produced without container isolation.** The experiments ran in a restricted subprocess, with network access blocked and resources capped, but not inside a sandbox that can contain what it runs. Treat the results as a demonstration of the pipeline rather than as a trustworthy measurement, and re-run under Docker before relying on them.

## Limitations

Read these results narrowly.

- **A negative result here does not refute the paper.** These experiments run at a fraction of the
  original scale. An effect that disappears when the model, the data, or the training budget shrinks
  may still be real at full scale; that is precisely what reduced-scale testing cannot tell us.
- **A positive result is not a reproduction.** It says the direction of the claim survived
  shrinking, not that the paper's numbers were reproduced.
- **Seed counts are small.** With a handful of seeds per arm, statistical power is low. An
  inconclusive verdict usually means there was not enough evidence either way, not that the effect
  is absent.
- **Absolute claims are never testable this way** and are recorded without being run.
- The reduced experiments were written from the paper's description, so they may differ from the
  authors' implementation in ways that matter.
