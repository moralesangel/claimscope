## Tested claims

### mnist_dropout_reduces_errors

> Using 50% dropout on hidden units with L2 weight constraints reduces MNIST test errors from 160 (best published feedforward net without tricks) to about 130.

Source: Fig. 1 / Sec. main text (MNIST) · Metric: number of test errors · Expected: dropout_network < baseline_feedforward_network

**Verdict: Inconclusive**

dropout_network: 0.07444 (sd 0.00888, n=5); baseline_feedforward_network: 0.07262 (sd 0.00864, n=5). Effect in the predicted direction: +0.001821 [95% CI -0.00765, +0.01154], Welch p=0.751.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** On full MNIST (60k train / 10k test), a feedforward neural net trained normally achieves 160 test errors; adding 50% dropout on hidden units together with L2 (max-norm) weight constraints reduces this to about 130 test errors, i.e. dropout regularizes a large feedforward net that otherwise overfits.

**Reduced setup.** Use sklearn's 8x8 digits dataset (1797 images, 10 classes) standing in for MNIST. Split into a small training set (150 examples, 15/class) and a held-out test set (~650 examples) to force overfitting in an otherwise capable network. Train a hand-written numpy 2-layer MLP (64-256-256-10, tanh hidden activations, softmax output, cross-entropy loss) with plain minibatch gradient descent for 300 epochs, batch size 16, fixed learning rate. Two arms: (1) baseline_feedforward_network -- no dropout, no weight constraint; (2) dropout_network -- same architecture with 50% dropout on both hidden layers during training plus an L2/max-norm-style weight clipping (clip each hidden unit's incoming weight vector to a fixed max norm after each update), same optimizer/epochs/lr otherwise. Both arms use identical train/test split, same weight initialization scheme (per-seed), same number of epochs and batch size. Run 5 seeds per arm (1,2,3,4,5), record final test error count out of ~650, average across seeds.

**Why the claim should transfer.** Dropout's regularizing mechanism -- preventing complex co-adaptations of hidden units by randomly zeroing them during training, combined with keeping weight norms bounded -- is a general property of overfitting feedforward networks, not something tied to MNIST's specific pixel scale or dataset size. The claim's direction (dropout reduces test errors relative to an otherwise-identical undropped net) depends only on the baseline overfitting appreciably; by shrinking the training set to 150 examples for a network with two 256-unit hidden layers, we deliberately create a large capacity-to-data ratio so the baseline memorizes its training set (near-zero training error) while generalizing poorly, mirroring the overfitting regime that motivated dropout in the original paper. In that regime, adding dropout should reduce the effective capacity used at any one time and constrain weight growth, narrowing the train/test gap and lowering test error count, exactly the mechanism claimed. Since both arms share every other detail (data, architecture, epochs, seeds, initialization), any systematic difference in test errors is attributable to dropout+weight-constraint, giving a fair, if small-scale, test of the claimed direction.

**Seeds per arm:** 5 · **Estimated cost:** 45 min · **Code source:** from_scratch

**Changes from the paper**

- MNIST (28x28, 60k/10k) replaced with sklearn 8x8 digits (1797 total) -- no network access is available; digits is the standard offline stand-in for small-image multiclass classification and preserves the essential structure (pixel-image, 10-class, moderate feature count) needed for a feedforward net's overfitting/regularization dynamics to appear.
- Training set shrunk to 150 examples (15 per class) instead of the full pool -- a small net trained on abundant data would not overfit and dropout would have nothing to regularize; a deliberately small, class-balanced training set with a much larger held-out test set recreates the high-capacity-relative-to-data regime the paper's claim depends on.
- Network reduced from the paper's larger MLP (with many more hidden units, possibly convolutional-like structure) to a 2-hidden-layer MLP with 256 units per layer -- still large relative to the 150-example training set (thousands of parameters vs. 150 points), so it retains enough capacity to memorize and overfit the small training set, which is exactly the condition dropout is claimed to fix.
- Training for 300 epochs of full-batch-equivalent minibatch descent instead of the paper's much longer training run -- kept long enough (many more epochs than needed for the small training set to be fit near-perfectly) so the baseline arm can reach near-zero training error and show a visible train/test gap, which is the signature needed for dropout's effect to be observable.
- Implemented from scratch in numpy (forward/backward pass, dropout mask, weight-norm clipping) since no deep learning framework is available -- the architecture (feedforward net, dropout on hidden units, L2/max-norm constraint) is preserved exactly as specified in the claim, only the implementation substrate changes.
- 5 seeds per arm rather than a single run -- reduces to a budget-compatible number while satisfying the invariant of at least 3 seeds, giving variance estimates given the tiny training set makes single-run results noisy.

**Deliberately preserved**

- The core architectural comparison: identical feedforward network topology and identical training procedure (optimizer, epochs, batch size, learning rate, initialization scheme) between arms except for the presence/absence of dropout + weight-norm constraint, exactly matching invariant 3.
- The mechanism under test -- 50% dropout on hidden units combined with an L2/max-norm weight constraint -- implemented as specified rather than replaced by a different regularizer (e.g., not swapped for plain L2 penalty alone or early stopping).
- A classification task with a visible train/test generalization gap in the baseline arm, which is the regime in which dropout's claimed benefit can mechanically appear.
- Same train/test split and same number of test examples evaluated per seed across both arms, so the metric (test error count) is directly comparable.

### mnist_input_dropout_further_reduces_errors

> Adding 20% dropout of input pixels on top of 50% hidden dropout further reduces MNIST test errors to about 110.

Source: Fig. 1 · Metric: number of test errors · Expected: errors decrease with added input dropout compared to hidden-only dropout

**Verdict: Inconclusive**

hidden_and_input_dropout: 0.05936 (sd 0.013, n=5); hidden_dropout_only: 0.06086 (sd 0.0116, n=5). Effect in the predicted direction: -0.001503 [95% CI -0.01503, +0.0119], Welch p=0.852.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** On MNIST (60k train / 10k test, 28x28 images), a feedforward network trained with 50% dropout on hidden units achieves a certain test error; adding 20% dropout on the input pixels on top of the 50% hidden dropout further reduces test errors to about 110 (out of 10000).

**Reduced setup.** Use sklearn's 8x8 digits dataset (1797 images, 10 classes) standing in for MNIST. To induce a visible train/test overfitting gap despite the tiny dataset, use only 200 training examples (randomly sampled, stratified) and hold out the remaining ~1597 as test. Train a numpy-implemented MLP with one hidden layer of 800 units (wide relative to the 64 input features, to encourage overfitting), ReLU activations, softmax output, trained via mini-batch SGD (batch size 32) for 300 epochs with a fixed learning rate (0.1) and no weight decay, early stopping, or other regularizer besides the dropout under test. Two arms: (a) hidden_dropout_only: 50% dropout applied to the hidden layer activations during training; (b) hidden_and_input_dropout: same 50% hidden dropout plus 20% dropout applied to the input pixels during training. Both arms use identical architecture, data split, batch size, epochs, and learning rate; only the input-dropout mask differs. Report test error count (out of ~1597) for each arm, averaged over seeds.

**Why the claim should transfer.** Dropout's regularizing mechanism (noise injection during training that prevents units, or in the input-dropout case pixels, from being relied upon too heavily, thereby reducing co-adaptation and overfitting) is architecture- and scale-free: it depends on the existence of a train/test generalization gap, not on the absolute size of the network or dataset. By deliberately shrinking the training set to 200 examples with a wide hidden layer (800 units) trained for many epochs without other regularization, the reduced setup manufactures the same overfitting regime that the paper's larger MNIST network shows, giving hidden dropout room to help and giving input dropout additional room to help beyond that. Since the claim is specifically about the *incremental, additive* effect of input dropout on top of hidden dropout, and both arms are run with identical architecture, data, and hyperparameters differing only in whether input-pixel dropout is applied, any systematic decrease in test errors for the input+hidden arm relative to hidden-only across seeds would be a direct, uncounfounded signal that the direction of the paper's claim replicates in miniature. The main risk is that at this tiny scale, input dropout could be too aggressive (dropping 20% of only 64 pixels loses more relative information than dropping 20% of 784 MNIST pixels), which could weaken or reverse the effect for reasons of scale rather than mechanism; this is noted as a limitation but does not by itself argue the direction should flip, since input dropout at 20% is still a modest noise level relative to the 8x8 grid's redundancy in digit shapes.

**Seeds per arm:** 5 · **Estimated cost:** 45 min · **Code source:** from_scratch

**Changes from the paper**

- MNIST (28x28, 70k images) replaced by sklearn 8x8 digits (1797 images) -- no network access is available; digits is the standard small stand-in for MNIST-style image classification and preserves the same qualitative structure (small pixel-grid, 10-class digit classification), so a dropout-on-pixels effect should manifest analogously.
- Training set restricted to 200 examples instead of 60k -- with the full 1797-image dataset a small MLP does not overfit enough for dropout to have room to act (as with 10-epoch full-digits training test error is already ~5%). Subsampling to 200 examples and using a wide (800-unit) hidden layer for many epochs (300) with no other regularizer recreates the train/test overfitting gap the paper's setup relies on, which is the precondition for dropout (hidden or input) to reduce test error at all.
- Implemented from scratch in plain numpy (no PyTorch/TensorFlow) -- only numpy and scikit-learn are available; a single hidden-layer MLP with manual forward/backward pass and dropout masks is a direct, faithful reduction of the paper's feedforward network and does not change the mechanism being tested.
- Fixed learning rate and epoch budget (300) with no tuning -- kept identical across both arms so any difference in test error is attributable only to the presence/absence of input dropout, per invariant 1.
- Error counted out of ~1597 held-out digits instead of MNIST's 10000 test images -- the metric (number of test errors) is kept in kind (a count) but on a smaller test set; the direction of the comparison (does adding input dropout reduce the count) is what's evaluated, not the absolute count of ~110.

**Deliberately preserved**

- The core architecture: a feedforward MLP with one hidden layer, ReLU (paper likely used similar or sigmoid units but ReLU is a standard, safe stand-in for the same regularization mechanism), softmax output for multi-class digit classification.
- The dropout mechanism itself: 50% hidden-unit dropout as the baseline arm, with 20% input-pixel dropout added on top in the treatment arm, applied via random binary masks during training exactly as in the paper's ablation.
- Training via mini-batch SGD, matching the paper's optimization regime (no adaptive optimizer tricks that could confound the comparison).
- Identical data split, batch size, epochs, learning rate, and initialization scheme across both arms except for the seed and the presence/absence of input dropout -- isolating the causal variable per invariant 1.
- A regime with a genuine train/test generalization gap in the baseline arm, which is the necessary condition for any dropout-based effect (hidden-only or hidden+input) to be observable at all.

## Claims not tested

- **`dbn_finetune_dropout_beats_backprop`** (comparative) — Fine-tuning a pretrained deep belief network with 50% dropout gives 92 errors on MNIST, compared to 118 errors using standard backpropagation fine-tuning. _Requires pretraining a deep belief network (unsupervised layer-wise pretraining) before fine-tuning, which is too costly and slow to fit a 60-minute CPU-only budget with 3 seeds per arm._
- **`dbm_dropout_record_mnist`** (comparative) — Fine-tuning pretrained deep Boltzmann machines with 50% dropout achieves a mean of 79 errors on MNIST, a record for methods without prior knowledge or enhanced training sets, compared to a mean of about 95 errors with standard backpropagation fine-tuning. _Requires pretraining a deep Boltzmann machine, an expensive iterative generative training procedure unsuitable for a small CPU-only budget._
- **`timit_dropout_improves_frame_classification`** (comparative) — Dropout of 50% of hidden units and 20% of input units improves frame classification error rate on the TIMIT core test set across multiple network architectures. _TIMIT preprocessing and multiple architecture comparisons at meaningful scale exceed a 60-minute CPU-only budget for speech feature extraction and training._
- **`timit_recognition_rate_improvement`** (comparative) — Using dropout improves the TIMIT phone recognition error rate from 22.7% without dropout to 19.7% with dropout, setting a record for methods that do not use speaker identity information. _Achieving competitive phone recognition rates requires substantial acoustic model training and decoding infrastructure that cannot be reproduced, even approximately, within a small CPU-only budget._
- **`cifar10_dropout_improves_error`** (comparative) — A convolutional network for CIFAR-10 achieves 16.6% test error without dropout, improving to 15.6% when 50% dropout is applied in the last hidden layer, both better than the previous best published 18.5% error. _Training a convolutional network on CIFAR-10 to any informative accuracy typically requires many GPU-hours; on CPU only this cannot fit within 60 minutes across seeds and arms._
- **`imagenet_dropout_record`** (comparative) — A single convolutional neural network on ImageNet achieves 48.6% top test error without dropout, and 42.4% error with 50% dropout in the sixth hidden layer, setting a new record versus the prior state-of-the-art of 45.7%. _Both the absolute record numbers and the underlying full ImageNet-scale convolutional network training are far beyond a CPU-only 60-minute budget, and the claim is inherently tied to large-scale results._
- **`reuters_dropout_improves_classification`** (comparative) — A feedforward network on the Reuters dataset achieves 31.05% test error with standard backpropagation, reduced to 29.62% using 50% dropout. _A feedforward network on a bag-of-words style Reuters text classification task is cheap on CPU, and the direction that dropout improves generalization plausibly transfers to a small subsampled version._
- **`imagenet_globally_connected_layers_need_dropout`** (ablation) — Adding non-convolutional, globally-connected higher layers with many parameters to the ImageNet architecture improves performance when combined with dropout but worsens performance without dropout, indicating dropout is essential to prevent overfitting in these high-capacity layers. _This claim is inherently about large, high-capacity globally-connected layers on ImageNet-scale data, an effect the paper attributes to capacity/scale that would not manifest in a shrunk setup._

## How these experiments were run

> **These results were produced without container isolation.** The experiments ran in a restricted subprocess, with network access blocked and resources capped, but not inside a sandbox that can contain what it runs. Treat the results as a demonstration of the pipeline rather than as a trustworthy measurement, and re-run under Docker before relying on them.

## Limitations

Read these results narrowly.

- **A negative result here does not refute the paper.** These experiments run at a fraction of the
  original scale. An effect that disappears when the model, the data, or the training budget shrinks
  may still be real at full scale; that is precisely what reduced-scale testing cannot tell us.
- **A positive result is not a reproduction.** It says the direction of the claim survived
  shrinking, not that the paper's numbers were reproduced.
- **Seed counts are small.** With a handful of seeds per arm, statistical power is low. An
  inconclusive verdict usually means there was not enough evidence either way, not that the effect
  is absent.
- **Absolute claims are never testable this way** and are recorded without being run.
- The reduced experiments were written from the paper's description, so they may differ from the
  authors' implementation in ways that matter.
