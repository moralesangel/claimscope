## Tested claims

### cifar_mixup_beats_erm

> On both CIFAR-10 and CIFAR-100, models trained with mixup significantly outperform their ERM-trained counterparts across PreAct ResNet-18, WideResNet-28-10, and DenseNet-BC-190 architectures.

Source: Figure 3a · Metric: test error · Expected: mixup < ERM

**Verdict: Inconclusive**

mixup: 0.04899 (sd 0.00714, n=3); erm: 0.05322 (sd 0.0113, n=3). Effect in the predicted direction: +0.004231 [95% CI -0.008239, +0.01625], Welch p=0.618. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** On CIFAR-10 and CIFAR-100, PreAct ResNet-18, WideResNet-28-10, and DenseNet-BC-190 are trained for ~200 epochs with SGD, comparing standard ERM training to mixup (convex combinations of input pairs and labels with alpha=1 or 0.2), showing mixup gives significantly lower test error across all three architectures.

**Reduced setup.** Use sklearn's 8x8 digits dataset (1797 images, 10 classes) standing in for CIFAR-10, since CIFAR cannot be downloaded. Use only ~300 training images (small stratified subset) and the full remaining ~1497 as test, to force a train/test gap. Implement a small numpy MLP (64-32-10, i.e. one hidden layer of 32 units, roughly analogous in role to a compact CNN) trained with manual forward/backward pass and plain minibatch SGD (batch size 16) for 300 epochs -- this is the 'architecture' to preserve in spirit (a single fixed model family, no architecture swap between arms). Two arms: ERM (train on raw batches, softmax cross-entropy) vs mixup (same model/optimizer/epochs, but each batch is a mixup of two randomly paired examples and one-hot labels with alpha=0.2, matching the paper's default). Both arms get identical data split, identical initialization scheme (different per seed), identical epoch budget and batch size. Run 3 seeds per arm (6 runs total), each run trains in well under a minute on CPU.

**Why the claim should transfer.** Mixup's claimed benefit is a regularization effect: by training on convex combinations of inputs and labels, the model is discouraged from memorizing sharp decision boundaries around individual training points, which reduces overfitting and lowers test error relative to ERM. This mechanism is architecture- and dataset-agnostic in principle -- it operates on the loss and input pairs, not on convolutional structure or image resolution specifically. The reduced setup deliberately uses only ~300 training digits images (vs ~1500+ held out for test) with a moderately expressive MLP (64-32-10) trained for 300 epochs with no early stopping, which is enough capacity and enough epochs for the ERM arm to drive training loss to near zero while test error stays visibly higher -- i.e., a real train/test gap, the exact regime in which mixup is designed to help. If mixup cannot narrow that gap and reduce test error in this small, controlled, overfitting-prone regime, that is genuine evidence against the direction of the claim; if it can, that supports transfer of the paper's finding. The main risk is that with only 3 features effectively distinguishing 10 digit classes and an MLP rather than a CNN, the interpolated mixup examples may be less 'informative' than mixed natural images, potentially understating the effect size -- but the qualitative direction (mixup test error < ERM test error) should still be testable given the deliberately engineered overfitting gap.

**Seeds per arm:** 3 · **Estimated cost:** 12 min · **Code source:** from_scratch

**Changes from the paper**

- CIFAR-10/100 -> sklearn load_digits (8x8, 10 classes) -- no network access is available so CIFAR cannot be fetched; digits is the documented stand-in for small image classification and preserves the core mechanism (soft interpolated labels regularizing a classifier prone to overfitting small data), which is what the claim is actually about.
- PreAct ResNet-18/WideResNet-28-10/DenseNet-BC-190 -> single small numpy MLP (64-32-10) -- no deep learning framework is installed, so convolutional architectures cannot be built; a single fixed, modestly-sized model is used identically for both arms so the comparison isolates the mixup vs ERM difference rather than architecture choice, satisfying invariant 3's spirit at the scale sklearn/numpy allow.
- 200 epochs -> 300 epochs on ~300 training examples -- epoch count is increased (not the direction-critical parameter) because the tiny model/tiny dataset needs enough steps to fit and start overfitting on this reduced scale; this does not favor either arm since both get identical epoch budgets.
- Full CIFAR training set (50k/100k images) -> small stratified subset of ~300 digits images -- shrinking data size is necessary to fit the CPU/time budget and, importantly, is required to induce the overfitting regime (train/test gap) that mixup's regularization is designed to close; without it neither arm would show a difference.
- SGD with momentum/weight decay/LR schedule -> plain minibatch SGD with fixed learning rate -- schedule/momentum details are optimization plumbing not central to the mixup-vs-ERM comparison, and are applied identically to both arms so they cannot advantage one arm over the other.
- alpha=1 (paper's main CIFAR setting) -> alpha=0.2 -- alpha=0.2 is also used in the paper's own ablations and gives mild-to-moderate mixing, which is safer at very small sample sizes (large alpha with alpha=1 can produce overly aggressive interpolation when there are only ~300 points per class distribution); this is a conservative same-family choice, not a directionally biased one.

**Deliberately preserved**

- The core mixup mechanism: convex combination of pairs of inputs and their one-hot labels used as training targets, versus untouched ERM training on the same batches.
- Identical model architecture, initialization scheme, optimizer type, batch size, number of epochs, and train/test split across both arms -- the only difference is whether batches are mixed.
- A genuine train/test performance gap in the ERM arm (small training set forces the network to memorize rather than generalize), which is the precondition for any regularizer, including mixup, to show a measurable benefit.
- At least 3 independently seeded runs per arm so the comparison is not a single noisy draw.

### speech_mixup_beats_erm_vgg

> On the Google commands speech dataset, mixup outperforms ERM, with the largest gains observed for the higher-capacity VGG-11 model.

Source: Sec. 3.3 / Table (Fig. 4) · Metric: classification error · Expected: mixup < ERM

**Verdict: Inconclusive**

mixup_vgg11: 0.07467 (sd 0.00611, n=3); erm_vgg11: 0.076 (sd 0.0111, n=3). Effect in the predicted direction: +0.001333 [95% CI -0.01067, +0.01267], Welch p=0.867. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** On the Google Commands speech dataset, mixup and ERM are used to train a VGG-11 CNN on spectrogram-like input features for a 30-class keyword spotting task; mixup's classification error is compared to ERM's, with the claim that mixup gives the largest error reduction for the higher-capacity VGG-11 model relative to smaller models.

**Reduced setup.** Use sklearn's 8x8 digits dataset (1797 images, 10 classes) as a stand-in for Google Commands spectrograms (both are small fixed-size 2D "image-like" grids fed to a CNN/MLP classifier). Implement a small numpy CNN-like architecture (a single hidden dense layer, treated as a scaled-down 'VGG-11' analogue: one moderately wide hidden layer of 256 units with ReLU, since a full multi-conv-layer VGG-11 in raw numpy is infeasible in the time budget) trained on a reduced training subset (300 images) to induce overfitting, with a held-out test set of 500 images. Two arms: ERM (train on raw one-hot labels + cross-entropy) vs mixup (train on linear interpolations of pairs of images/one-hot labels with lambda~Beta(0.2,0.2), same architecture, same epochs, same optimizer). Train for 60 epochs with plain SGD, batch size 32, learning rate 0.1, 3 seeds per arm (6 runs total), each run capped to well under 10 minutes CPU.

**Why the claim should transfer.** The claim's core mechanism is that mixup's soft, interpolated training signal acts as a data-dependent regularizer that most benefits models with enough capacity to overfit the (relatively) small/finite training set -- exactly the VGG-11-vs-smaller-model contrast in the paper. By keeping the essential ingredients -- (a) a high-capacity model relative to a restricted training set so ERM visibly overfits (train accuracy near 100%, test error well above train error), and (b) the exact mixup interpolation mechanism applied identically across arms -- the reduced setup reconstructs the regime the claim depends on, even though the modality (digits vs speech spectrograms) and architecture depth (single wide layer vs deep VGG stack) differ. Mixup's regularizing effect (smoother decision boundaries, reduced memorization of exact training examples) is architecture- and modality-agnostic in the original paper's own experiments (they show it across CIFAR, ImageNet, speech, and various architectures), so testing it on a different but structurally analogous overfitting-prone classification task with the same interpolation mechanism should preserve the sign of the effect (mixup error < ERM error), even if the *magnitude* of the gap (and the specific claim about VGG-11 being the *largest* beneficiary among several models) cannot be tested here since we only reduce to a single capacity level, not multiple model sizes for a magnitude-ranking comparison.

**Seeds per arm:** 3 · **Estimated cost:** 45 min · **Code source:** from_scratch

**Changes from the paper**

- Google Commands speech spectrograms -- replaced with sklearn 8x8 digit images: no network access is available so the real dataset cannot be fetched; digits give a small, fixed-size, multi-class image classification task with a visible train/test gap when data is restricted, which is the property the claim exploits (regularization helping under overfitting), so the direction of the effect is not tied to the audio domain specifically.
- VGG-11 CNN -- replaced with a single wide dense hidden layer (256 units) numpy MLP: no deep learning framework is available, so genuine convolutions and deep VGG-style stacks cannot be implemented from scratch in the time budget; a single wide, high-capacity layer preserves the paper's variable of interest (a higher-capacity model on a small dataset that overfits), which is the mechanism the claim is actually testing (higher capacity models overfit more, so mixup shows larger relative gains) even though the literal 'VGG-11 depth' is not reproduced.
- Reduced training set to 300 images (from thousands of Google Commands training clips) -- to force visible overfitting in the ERM arm within a modest hidden-layer network in the CPU time budget; without a train/test gap, no regularizer (mixup included) has anything to close, so this is necessary, not just convenient.
- 60 training epochs with SGD instead of the paper's full training schedule -- shortened purely for wall-clock budget; both arms get identical epochs, batch size, and learning rate, so this cannot differentially favor either arm.
- Mixup implemented directly on raw pixel vectors and one-hot labels via linear interpolation (lambda ~ Beta(0.2,0.2)), matching the paper's mixup formula but applied to non-image-conv input; this preserves the exact mixup mechanism (convex combination of inputs and labels) which is the object of the claim, independent of the specific architecture it is layered onto.

**Deliberately preserved**

- The mixup algorithm itself: convex combination of a pair of training examples and their one-hot labels using a lambda drawn from a Beta(0.2,0.2) distribution, exactly as in the original mixup formulation.
- The comparative ERM vs mixup framing: both arms trained with identical architecture, optimizer, epochs, batch size, seeds, and dataset, differing only in whether inputs/labels are mixed.
- A higher-capacity model relative to the data size (300 training examples vs a 256-unit hidden layer, i.e., a highly overparameterized regime), which is the condition under which the paper claims mixup's advantage is largest.
- A genuine train/test generalization gap in the ERM baseline, which is the necessary condition for any regularization method (mixup included) to show a measurable benefit.

## Claims not tested

- **`imagenet_mixup_beats_erm_resnet50`** (comparative) — On ImageNet, ResNet-50 trained with mixup achieves lower top-1 error than ERM training at 90 epochs. _Requires large-scale ImageNet pretraining of ResNet-50 for 90 epochs, which is infeasible on a CPU-only 60-minute budget._
- **`imagenet_mixup_beats_erm_resnext101`** (comparative) — On ImageNet, ResNeXt-101 64x4d trained with mixup achieves lower top-1 and top-5 error than ERM training. _Requires training a very large ResNeXt-101 model on full ImageNet, far exceeding CPU-only compute and time budget._
- **`imagenet_larger_models_benefit_more`** (scaling_trend) — Larger-capacity models and longer training runs benefit more from mixup, with ResNet-101 and ResNeXt-101 showing bigger error reductions than ResNet-50 at 90 epochs. _This is an explicit scale-dependent trend (bigger models/longer training benefit more), and also requires ImageNet-scale training that cannot fit the budget._
- **`mixup_reduces_label_memorization`** (comparative) — With large alpha values, mixup outperforms dropout at resisting memorization of corrupted labels on CIFAR-10, achieving lower test error and lower training error on real labels while remaining resistant to noisy labels. _Corrupted-label CIFAR-10 experiments with mixup vs dropout can be run on a small subset with few epochs, and the qualitative robustness-to-noisy-labels direction is plausible to preserve at reduced scale._
- **`mixup_plus_dropout_best_corrupted_labels`** (ablation) — Combining mixup and dropout yields the best performance of all methods tested on corrupted-label CIFAR-10 experiments, better than either method alone. _This ablation (mixup+dropout vs each alone) can be run on a small corrupted-label CIFAR-10 subset within budget, and combination effects are architecture/scale-independent enough to plausibly transfer._
- **`mixup_robust_adversarial_whitebox`** (comparative) — A mixup-trained ResNet-101 is substantially more robust to white-box FGSM adversarial attacks than an ERM-trained ResNet-101, showing about 2.7x lower top-1 error under attack. _Depends on ResNet-101 trained on full ImageNet before adversarial evaluation, which cannot be reproduced under a CPU-only 60-minute budget._
- **`mixup_robust_adversarial_blackbox`** (comparative) — A mixup-trained ResNet-101 is more robust to black-box FGSM and I-FGSM adversarial attacks than an ERM-trained ResNet-101, with about 1.25x lower top-1 error for FGSM and about 40% lower error for I-FGSM. _Requires an ImageNet-scale ResNet-101 model to generate and transfer black-box adversarial examples, infeasible on CPU-only reduced compute._
- **`mixup_best_ablation_data_augmentation`** (ablation) — Among all tested data augmentation and interpolation variants in the ablation study, standard mixup (interpolating raw inputs and labels between random pairs across all classes) achieves the lowest test error, significantly better than the next best alternative (input mixing plus label smoothing). _This is a small-model ablation over augmentation variants on a small dataset, so all arms are cheap to run and the relative ranking of variants likely transfers at reduced scale._

## How these experiments were run

> **These results were produced without container isolation.** The experiments ran in a restricted subprocess, with network access blocked and resources capped, but not inside a sandbox that can contain what it runs. Treat the results as a demonstration of the pipeline rather than as a trustworthy measurement, and re-run under Docker before relying on them.

## Limitations

Read these results narrowly.

- **A negative result here does not refute the paper.** These experiments run at a fraction of the
  original scale. An effect that disappears when the model, the data, or the training budget shrinks
  may still be real at full scale; that is precisely what reduced-scale testing cannot tell us.
- **A positive result is not a reproduction.** It says the direction of the claim survived
  shrinking, not that the paper's numbers were reproduced.
- **Seed counts are small.** With a handful of seeds per arm, statistical power is low. An
  inconclusive verdict usually means there was not enough evidence either way, not that the effect
  is absent.
- **Absolute claims are never testable this way** and are recorded without being run.
- The reduced experiments were written from the paper's description, so they may differ from the
  authors' implementation in ways that matter.
