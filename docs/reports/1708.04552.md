## Tested claims

### resnet18_cutout_cifar10

> Adding cutout to ResNet18 reduces test error on CIFAR-10 (with standard augmentation) from 4.72% to 3.99%.

Source: Table 1 · Metric: test error rate · Expected: resnet18_cutout < resnet18_baseline

**Verdict: Inconclusive**

resnet18_cutout: 0.1018 (sd 0.0117, n=3); resnet18_baseline: 0.09269 (sd 0.00608, n=3). Effect in the predicted direction: -0.009107 [95% CI -0.02186, +0.001619], Welch p=0.319. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** On CIFAR-10 with standard data augmentation, a ResNet18 trained with cutout regularization achieves 3.99% test error, compared to 4.72% test error for the same ResNet18 trained without cutout (Table 1).

**Reduced setup.** Using sklearn's 8x8 digits dataset (1797 images, 10 classes) as a stand-in for CIFAR-10, train a small numpy-implemented MLP (784->... actually 64 input -> 128 hidden -> 10 output, single hidden layer, ReLU) from scratch with manual forward/backward pass, using a small training subset (e.g. 150 images, ~15 per class) to force overfitting, and full held-out test set (remaining ~1647 images) for evaluation. Two arms: (1) baseline -- no augmentation/regularization; (2) cutout-analogue -- randomly zero out a contiguous square patch (e.g. 2x2 to 3x3 pixels) of each 8x8 training image on every epoch (the closest small-image analogue of CIFAR cutout's patch-masking augmentation). Train both arms for 200 full-batch gradient descent epochs with the same learning rate, weight init, and hyperparameters, differing only in whether cutout-style patch masking is applied to training images. Run 3 seeds per arm (different random weight inits, subset draws, and patch placement RNG), fixing everything except cutout on/off between paired seeds.

**Why the claim should transfer.** Cutout's claimed benefit is a general regularization mechanism: randomly occluding rectangular patches of training images forces a model to not over-rely on any single localized feature, reducing overfitting and thus test error, and this argument does not depend on CIFAR-10 scale or ResNet depth specifically. The key precondition for the effect to be visible is that the baseline model actually overfits its training data -- by deliberately shrinking the training set to ~150 8x8-pixel images while keeping a much larger held-out test set, and training long enough (200 full-batch epochs) to reach near-zero training loss, the baseline arm should show a visible train/test performance gap, exactly the situation cutout is designed to address. Because the cutout-analogue arm applies the same occlusion idea (random patch zeroing) proportionally scaled to the smaller image size, and everything else (architecture, subset, epochs, seeds) is identical between arms, any systematic decrease in test error for the cutout arm across seeds would be evidence that the direction of the claimed effect transfers to this much smaller regime. The main risk is that 8x8 images are too small/low-resolution for patch occlusion to carry the same informational disruption as on 32x32 CIFAR-10 images, which could weaken but should not reverse the effect's direction.

**Seeds per arm:** 3 · **Estimated cost:** 25 min · **Code source:** from_scratch

**Changes from the paper**

- Dataset: sklearn 8x8 digits (1797 images) instead of CIFAR-10 -- no network access is available so CIFAR-10 cannot be downloaded; digits is the only small image-classification dataset available and preserves the core mechanism (occluding part of an image as augmentation), so the direction of the effect (masking regularizes, lowers test error) should still be visible.
- Architecture: single-hidden-layer numpy MLP (64->128->10) instead of ResNet18 -- no deep learning framework is installed, so a hand-written convnet/resnet is infeasible in 60 CPU-minutes; the claim is about the *regularization effect of cutout*, not about ResNet-specific mechanisms, so a smaller feed-forward network with the same overfitting-then-regularizing dynamic should still show the same directional effect.
- Training subset reduced to ~150 images (~15/class) instead of the full 50k CIFAR-10 training set -- this is necessary to force visible overfitting (train/test gap) within a tiny model and short training budget, which is the regime cutout is designed to help; using the full 1797-image dataset would likely not overfit enough for regularization to matter.
- Cutout adapted to 2x2/3x3 pixel patch zeroing on 8x8 images instead of the paper's 16x16 patch on 32x32 images -- patch size is scaled proportionally (~25-35% of image dimension in both cases) to preserve the relative occlusion strength that drives the regularization effect.
- Training for 200 full-batch gradient-descent epochs instead of the paper's many-epoch SGD schedule with learning-rate decay -- full-batch GD on 150 examples converges quickly and deterministically per seed, and 200 epochs is enough to reach a memorization regime on such a small subset, making it comparable in spirit to the paper's long training run that also reaches near-zero train error.
- 3 seeds per arm instead of the paper's likely single reported run (or unspecified number) -- required by invariant 2 to assess whether the direction of the effect is robust to random variation, not a reduction of the claim itself.

**Deliberately preserved**

- The comparative structure: identical architecture, dataset, training subset, epochs, learning rate, and initialization scheme between the two arms -- the only difference is presence/absence of cutout-style patch masking during training, isolating the causal factor the claim is about.
- The direction being tested: does adding an occlusion-based augmentation reduce test error relative to no such augmentation, holding everything else fixed.
- A regime where the baseline overfits (small training subset, no other regularization) so that there is a train/test gap for cutout to actually close -- without this, the comparison would be uninformative regardless of correctness.

### cutout_size_parabolic_trend

> As the cutout patch size increases from small to large, validation accuracy on CIFAR-10 and CIFAR-100 first increases then decreases in a parabolic trend, eventually falling below the no-cutout baseline for very large patch sizes.

Source: Fig. 3a, 3b · Metric: validation accuracy · Expected: accuracy increases then decreases as patch size grows

**Verdict: Not consistent at reduced scale**

treatment: 0.6456 (sd 0.0291, n=3); control: 0.9189 (sd 0.0077, n=3). Effect in the predicted direction: -0.2733 [95% CI -0.3056, -0.2489], Welch p=0.00227. With 3 seeds per arm this test has low power: an inconclusive result means insufficient evidence, not absence of an effect.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** On CIFAR-10 and CIFAR-100, a WideResNet (e.g. WRN-28-10) is trained with Cutout data augmentation, sweeping the square cutout patch size from small to large (e.g. 0 to 26+ pixels on 32x32 images), and validation accuracy is plotted against patch size (Fig. 3a, 3b), showing a rise-then-fall parabolic trend that eventually drops below the no-cutout baseline for very large patches.

**Reduced setup.** Use sklearn's 8x8 digits dataset (1797 images, 10 classes) as a stand-in for CIFAR-10/100. Reshape each digit to an 8x8 grid and implement "cutout" by zeroing out a random square patch of side length k within the image before feeding it to a small hand-written 2-layer MLP (64 -> 32 -> 10, numpy/sklearn-compatible via manual forward/backward or via sklearn's MLPClassifier with partial_fit) trained on only 150 training examples (to force overfitting) for 200 epochs, batch size 32, full-batch SGD. Sweep cutout patch size k over {0 (baseline), 1, 2, 3, 4, 5, 6, 7} pixels (0 to nearly full image side of 8), applying a freshly random patch location per training example per epoch. Evaluate on a held-out validation set of 300 examples not used in training. Each patch-size value is one arm-point; run 3 seeds (different random splits + patch placements + weight inits) per patch size. Compare against the no-cutout (k=0) baseline arm to detect the same-direction parabolic trend: rise then fall below baseline for very large k.

**Why the claim should transfer.** The parabolic trend in the paper is explained by an information-theoretic/regularization tradeoff: small cutout patches remove little information and provide mild useful regularization (accuracy rises above baseline), while very large patches remove so much of the input that the label becomes unrecoverable from the remaining pixels for many examples, hurting accuracy below baseline. This mechanism is architecture- and dataset-scale agnostic; it only requires (a) a model capable of overfitting without augmentation, and (b) an input structure where occluding pixels can plausibly destroy class-discriminative information. Both conditions are engineered into the reduced setup: 150 training examples relative to even a tiny 64-32-10 MLP produces a clear train/test gap at k=0 (overfitting), and on 8x8 digit images, occluding half or more of the 64 pixels with a contiguous patch removes strokes that are necessary to distinguish e.g. a '3' from an '8' or a '1' from a '7', mirroring the occlusion-destroys-information regime that drives the downturn in the original curve. Because the sweep spans from no occlusion to near-total occlusion, and because the model's capacity/dataset-size ratio is deliberately kept in the overfitting regime, the same rise (mild regularization benefit) then fall (information destruction) shape should appear, even though absolute accuracies and the exact optimal patch size will differ from CIFAR. If the trend is not reproduced qualitatively at this reduced scale, it would suggest the parabolic shape genuinely depends on properties absent from this experiment (e.g. convolutional locality or natural image statistics), which is itself an informative negative result.

**Seeds per arm:** 3 · **Estimated cost:** 18 min · **Code source:** from_scratch

**Changes from the paper**

- CIFAR-10/100 (32x32 RGB, natural images) -> sklearn 8x8 digits (grayscale, handwritten digits) -- justified because Cutout's effect is a generic occlusion-based regularization mechanism that does not depend on image realism or channel count, only on the presence of an overfitting regime and a spatial patch that can occlude informative pixels.
- WideResNet-28-10 (36M params) -> small 2-layer MLP (64-32-10, ~2300 params) -- justified because the claim concerns the *shape of the accuracy-vs-patch-size curve* which the paper attributes to a regularization/information-loss tradeoff, not to convolutional structure; an MLP overfitting a small dataset still exhibits a train/test gap that cutout can close or overshoot.
- Full CIFAR train set (50k images) -> only 150 training examples -- justified to force a visible train/test accuracy gap in the k=0 baseline within a small MLP, since without overfitting there is no regularization effect for cutout to act on.
- Patch size range 0-26+ pixels on 32x32 -> 0-7 pixels on 8x8 -- justified as a proportionally equivalent sweep (0% to ~87% of image side) so both very small (little effect) and very large (near-total occlusion, expected below-baseline drop) regimes are represented.
- 200 training epochs, full-batch/small-batch SGD instead of paper's original training schedule (which uses SGD with momentum, weight decay, LR schedule over ~200 epochs on CIFAR) -- justified because what matters for the claim is that training converges enough to show the overfit/regularization interplay, not the exact optimizer schedule.
- 3 seeds per patch-size arm instead of paper's (unspecified, likely single-run) points -- justified to obtain a noise estimate given the invariant requirement and the small-data regime's higher variance.

**Deliberately preserved**

- The augmentation mechanism itself: randomly-located square patches of zeroed-out pixels applied during training, i.e. Cutout exactly as described, not replaced by another augmentation.
- A sweep over multiple patch sizes including a no-cutout baseline (k=0) and a patch size covering nearly the whole image, so both extremes of the claimed parabola can appear.
- An overfitting regime in the baseline (small training set relative to model capacity) so the regularization effect Cutout is claimed to produce has room to manifest.
- Held-out validation accuracy as the measured metric, matching the paper's metric.
- Same architecture, dataset, reduction, and seed count used identically across all patch-size arms, so the only varying factor is patch size (invariant 1).

## Claims not tested

- **`wideresnet_cutout_cifar10`** (comparative) — Adding cutout to WideResNet-28-10 reduces test error on CIFAR-10 (with standard augmentation) from 3.87% to 3.08%. _A shrunk WideResNet (fewer widen factor/blocks) on a CIFAR-10 subset can still show the regularization direction of cutout within a CPU budget._
- **`wideresnet_cutout_cifar100`** (comparative) — Adding cutout to WideResNet-28-10 reduces test error on CIFAR-100 (with standard augmentation) from 18.8% to 18.41%. _Same shrunk WideResNet setup applies to CIFAR-100 subset; the comparative direction of cutout vs baseline should hold at reduced scale._
- **`shake_shake_cutout_cifar10_sota`** (comparative) — Applying cutout to shake-shake regularization models achieves a new state-of-the-art test error of 2.56% on CIFAR-10, improving over the 2.86% baseline. _Shake-shake regularization models are computationally heavy (long training schedules, complex branching architectures) and the claim is framed as an absolute state-of-the-art number, making it infeasible on a CPU-only 60-minute budget._
- **`shake_shake_cutout_cifar100_sota`** (comparative) — Applying cutout to shake-shake regularization models achieves a new state-of-the-art test error of 15.20% on CIFAR-100, improving over the 15.85% baseline. _Same as above: shake-shake models are too expensive for CPU-only reduced-scale training and the claim centers on an absolute SOTA number._
- **`wideresnet_cutout_svhn_sota`** (comparative) — Applying cutout to WRN-16-8 on SVHN reduces test error by about 0.3 percentage points, achieving a new state-of-the-art of 1.30% versus 1.60% baseline. _Framed as achieving an absolute state-of-the-art number (1.30%), which by construction cannot be validated at reduced scale._
- **`stl10_cutout_no_aug`** (comparative) — Applying cutout to a WideResNet on STL-10 without data augmentation reduces test error by 2.7 percentage points (23.48% to 20.77%). _STL-10 images are larger (96x96) with fewer labeled examples per class, making training computationally heavier per image and the claim is stated as a specific absolute percentage-point reduction that won't reproduce at reduced scale, though the underlying comparative direction could work if reframed._
- **`stl10_cutout_with_aug`** (comparative) — Applying cutout to a WideResNet on STL-10 with standard data augmentation reduces test error by 1.5 percentage points (14.21% to 12.74%). _Same STL-10 image-size and absolute-number issues as above make this infeasible within the CPU budget as stated._
- **`optimal_cutout_size_decreases_with_classes`** (scaling_trend) — The optimal cutout patch size decreases as the number of classes in the dataset increases, since fine-grained classification relies more on small nuanced details than broad context. _This claim is explicitly attributed by the paper to dataset/class-count characteristics (a scale-dependent property of fine-grained vs coarse classification) rather than a simple ablation, making its direction unreliable to test by merely shrinking the setup._

## How these experiments were run

> **These results were produced without container isolation.** The experiments ran in a restricted subprocess, with network access blocked and resources capped, but not inside a sandbox that can contain what it runs. Treat the results as a demonstration of the pipeline rather than as a trustworthy measurement, and re-run under Docker before relying on them.

## Limitations

Read these results narrowly.

- **A negative result here does not refute the paper.** These experiments run at a fraction of the
  original scale. An effect that disappears when the model, the data, or the training budget shrinks
  may still be real at full scale; that is precisely what reduced-scale testing cannot tell us.
- **A positive result is not a reproduction.** It says the direction of the claim survived
  shrinking, not that the paper's numbers were reproduced.
- **Seed counts are small.** With a handful of seeds per arm, statistical power is low. An
  inconclusive verdict usually means there was not enough evidence either way, not that the effect
  is absent.
- **Absolute claims are never testable this way** and are recorded without being run.
- The reduced experiments were written from the paper's description, so they may differ from the
  authors' implementation in ways that matter.
