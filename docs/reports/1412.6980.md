### adam_vs_sgd_adagrad_logreg_mnist

> On MNIST logistic regression, Adam converges similarly to SGD with Nesterov momentum, and both converge faster than Adagrad.

Source: Fig. 1 / Sec. 6.1 · Metric: training negative log likelihood (convergence speed) · Expected: adam ≈ sgd_nesterov > adagrad

**Verdict: Inconclusive**

This claim compares 3 arms (adam, sgd_nesterov, adagrad), and the analysis can only settle a two-arm comparison. Testing adam against sgd_nesterov alone would answer a different question from the one the claim asks, so no verdict is given. The runs are in the workspace.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** The paper trains a multiclass logistic regression model on full MNIST (60k train images, 784-dim pixel features, 10 classes) using Adam, SGD with Nesterov momentum, and Adagrad, plotting training NLL vs. iteration/epoch to compare convergence speed.

**Reduced setup.** Multiclass logistic regression (single linear layer + softmax, no hidden units) on sklearn's `load_digits` (1797 images, 8x8=64 pixel features, 10 classes) standing in for MNIST. Features scaled to [0,1]. Full-batch gradient descent variants implemented by hand in numpy: (1) Adam, (2) SGD with Nesterov momentum, (3) Adagrad, each run for 300 iterations, logging training NLL (cross-entropy) every iteration. Learning rates tuned once per optimizer via a small fixed grid {0.001,0.01,0.1,0.5} on seed 0 only (train-loss based, not test-based, to avoid biasing the comparison), then fixed across all seeds. Each optimizer run with 5 seeds controlling data shuffling/train-test split and weight initialization (>=3 required); report mean+/-std training NLL curve per optimizer.

**Why the claim should transfer.** The claim is about the *relative* convergence behavior of three optimizers on a convex optimization problem (multiclass logistic regression), which is entirely determined by each optimizer's update rule interacting with the loss surface's curvature -- a property governed by the optimization mechanics, not by the specific image dataset's size or resolution. load_digits, like MNIST, gives pixel-intensity features for a 10-class image problem with correlated, non-orthogonal features, producing an ill-conditioned convex loss where Adagrad's aggressively-decaying per-coordinate learning rate is known to stall while Adam's bias-corrected moment estimates and Nesterov's momentum keep progressing -- this is exactly the mechanism the paper's Fig.1 illustrates, and it doesn't require MNIST's scale to manifest: 64 correlated pixel features already produce enough curvature variation across dimensions for Adagrad's monotonically shrinking step sizes to visibly lag. Using full-batch gradients (deterministic, no minibatch noise) actually sharpens the comparison by isolating each optimizer's adaptive step-size mechanics from stochastic noise, so if the ordering (adam ~ nesterov-sgd > adagrad) is a real property of the optimizers' interaction with a moderately ill-conditioned convex problem, it should reproduce here; if it doesn't reproduce even in this cleaner, noise-free regime, that is itself informative evidence against the claim's robustness.

**Seeds per arm:** 5 · **Estimated cost:** 12 min · **Code source:** from_scratch

**Changes from the paper**

- MNIST (60k, 784-dim) -> sklearn load_digits (1797, 64-dim) -- convergence-speed ordering of first-order optimizers on convex softmax loss depends on curvature/conditioning of the problem, not on absolute pixel count or resolution; both are pixel-intensity multiclass image classification with similar sparsity/scale structure, so relative ordering should transfer.
- Full dataset iterations/epochs replaced by 300 full-batch gradient steps on the whole (small) dataset instead of minibatch SGD over many epochs -- with only 1797 samples, full-batch is cheap and removes minibatch-noise as a confound, isolating the optimizer's deterministic update dynamics which is what the claim is really about (this is a convex problem, so full-batch gradient direction is the true gradient each optimizer adapts).
- Learning rate chosen via small grid on seed 0 only, then frozen for all seeds/arms -- avoids per-arm cherry-picking while giving each optimizer a reasonable operating point, since the claim is about relative convergence *given reasonable tuning*, not about optimizer default hyperparameters.
- Model architecture unchanged (single linear layer + softmax = multiclass logistic regression) -- required by invariant 3, and is exactly the model the claim is about.
- 5 seeds per arm instead of the paper's presumably single run -- gives variance estimates within the tight compute budget and satisfies the >=3 seed invariant.

**Deliberately preserved**

- The model class: multiclass logistic regression (convex loss surface), no architecture change.
- The three optimizer identities and their update rules (Adam, Nesterov SGD, Adagrad), implemented faithfully from their standard equations.
- The metric: training NLL (cross-entropy) tracked over optimization steps.
- Same dataset, same preprocessing, same number of steps, and same seeds across all three arms (only the optimizer differs).

### adam_better_dropout_mlp

> When training multilayer neural networks with dropout regularization, Adam shows better convergence than other stochastic first-order optimization methods.

Source: Fig. 2 / Sec. 6.2 · Metric: training cost convergence · Expected: adam > other optimizers

**Verdict: Inconclusive**

This claim compares 5 arms (adam, adagrad, rmsprop, sgd_nesterov, adadelta), and the analysis can only settle a two-arm comparison. Testing adam against adagrad alone would answer a different question from the one the claim asks, so no verdict is given. The runs are in the workspace.

#### Reduction plan

_This is what was **designed**. The experiment was then written by a model from this description, so read the script in the workspace to see what actually ran -- the two can differ, for instance where the sandbox has no network and the data had to be generated instead of downloaded._

**Original setup.** The paper trains multilayer neural networks with dropout regularization on standard benchmark datasets (e.g. MNIST-scale image classification), comparing Adam against Adagrad, RMSProp, SGD+Nesterov momentum, and Adadelta, and reports Adam's training cost (loss) converges faster/better across epochs (Fig. 2, Sec. 6.2).

**Reduced setup.** A from-scratch numpy MLP (784-ish input reduced to 64 input features -> 256 -> 256 -> 10, i.e. wider than needed relative to data size to induce overfitting) trained with dropout (p=0.5 on hidden units) on sklearn's 8x8 digits dataset (1797 images, 10 classes) standing in for MNIST, using only 300 training examples (random subset, fixed per seed) and the remaining ~1497 held out as test set to force a visible train/test gap. Each optimizer (Adam, Adagrad, RMSProp, SGD+Nesterov, Adadelta) is implemented by hand in numpy and run for 150 epochs, full-batch gradient computation but with dropout masks resampled each epoch (batch size = 300, i.e. full-batch, since data is tiny -- keeps runtime minimal while still stochastic via dropout masks and weight init). Training cost (cross-entropy loss on the 300 training points) is logged every epoch; convergence is compared as loss curve over epochs and final loss after 150 epochs.

**Why the claim should transfer.** The claim concerns the relative behavior of first-order stochastic optimizers when training loss is being minimized under dropout noise -- a mechanism governed by each optimizer's adaptive step-size/momentum properties interacting with per-step gradient noise (here injected by dropout masks and full-batch stochastic loss surface curvature), which is scale-free: it does not depend on dataset size or image resolution, only on there being a nontrivial non-convex, noisy optimization landscape with more than one layer of nonlinearity. By using only 300 training examples against a 256-256 hidden MLP, the baseline arm is pushed into a clear overfitting regime (visible train/test gap), which is precisely the condition under which dropout's regularizing noise is active and where optimizers' differing ability to convergence quickly and stably under that added stochasticity can be distinguished -- if the net did not overfit, dropout would contribute negligible noise and all optimizers would look similar regardless of the paper's claim. Keeping the architecture depth, per-arm identical data/init/budget, and dropout mechanism intact isolates the optimizer identity as the only causal difference, so a consistent ranking (Adam converging faster/lower on training loss across seeds) would be genuine evidence for the direction of the claim, while a reversal or no consistent ranking would be genuine evidence against it, at this reduced scale.

**Seeds per arm:** 5 · **Estimated cost:** 45 min · **Code source:** from_scratch

**Changes from the paper**

- MNIST -> sklearn load_digits (8x8, 1797 images) -- no network access is available; digits is the standard offline stand-in for small-scale image classification and preserves a genuine multi-class visual pattern-recognition problem.
- Full dataset (60k) -> 300-example training subset -- shrinks compute to CPU-friendly full-batch training while deliberately inducing an overfitting regime (small n, wide net) so dropout has something to regularize and optimizer differences in navigating the resulting noisy/non-convex loss surface can show up; without a train/test gap dropout is inert and the comparison would be uninformative.
- Network width narrowed to 256 hidden units (2 hidden layers) rather than paper's exact widths -- kept deep (multilayer, matching claim) and still large relative to the 300-sample training set to preserve overfitting capacity, only reduced from paper scale to fit CPU budget.
- 150 epochs instead of paper's training length -- full-batch on 300 points is cheap per step, so 150 epochs is enough for all optimizers to show distinct convergence trajectories within budget; loss curves are logged every epoch to see convergence speed differences, not just endpoint.
- Full-batch gradient descent instead of minibatch SGD -- since training set is only 300 points, full-batch is the natural minimal-compute choice; stochasticity in the arms still comes from dropout masks and random init/seed, preserving the 'stochastic first-order' regularized-training regime the claim is about.
- Optimizers implemented from scratch in numpy (no framework) -- required since no deep learning library is installed; standard update rules (Adam, Adagrad, RMSProp, Nesterov SGD, Adadelta) are simple closed-form formulas and can be faithfully implemented without a framework.

**Deliberately preserved**

- Multilayer (2 hidden layer) MLP architecture -- the claim is specifically about multilayer networks with dropout, not a linear model.
- Dropout regularization applied to hidden units during training -- this is the regularizer under test and must be present and active (overfitting regime ensures it has a real effect).
- All five optimizer arms (Adam, Adagrad, RMSProp, SGD+Nesterov, Adadelta) run under identical architecture, data, dropout rate, initialization scheme (per seed), and epoch budget -- only the optimizer update rule differs, respecting invariant 1.
- Same number of seeds, dataset split, and epoch budget across all arms.
- Training cost (loss) as the metric and convergence-over-epochs as the comparison criterion, matching the paper's Fig. 2 style presentation.

## Claims not tested

- **`adam_matches_adagrad_sparse_imdb`** (comparative) — On the sparse IMDB bag-of-words logistic regression task, Adam converges as fast as Adagrad, and both outperform SGD with Nesterov momentum by a large margin, with or without dropout. _Sparse bag-of-words logistic regression on a subsampled IMDB vocabulary/dataset is cheap on CPU and the sparsity-driven advantage of adaptive methods over SGD should still show at small scale._
- **`adam_faster_than_sfo_mlp`** (comparative) — On deterministic multilayer neural network training, Adam makes faster progress than the Sum-of-Functions Optimizer (SFO) in both iterations and wall-clock time, while SFO is 5-10x slower per iteration. _A small deterministic MLP and small SFO batch-of-subfunctions setup can run on CPU quickly, and the qualitative per-iteration/wall-clock speed comparison should still hold at reduced scale._
- **`sfo_fails_with_dropout`** (comparative) — The SFO optimizer, which assumes deterministic subfunctions, fails to converge when stochastic regularization (dropout) is applied, unlike Adam. _Both arms (SFO and Adam) can be run cheaply on a small MLP with dropout on CPU, and SFO's deterministic-subfunction assumption failing under dropout is a structural property, not a scale-dependent one._
- **`adam_sgd_beat_adagrad_cnn`** (comparative) — On CIFAR-10 CNN training, Adam and SGD with momentum eventually converge considerably faster than Adagrad over 45 epochs, despite Adagrad making rapid initial progress. _Training a CNN on CIFAR-10 for 45 epochs across multiple optimizers with 3 seeds per arm is far beyond a 60-minute CPU-only budget._
- **`adam_marginal_over_sgd_cnn`** (comparative) — On the CIFAR-10 CNN experiment, Adam shows only marginal improvement over SGD with momentum, but automatically adapts per-layer learning rates instead of requiring manual tuning. _This requires the same CIFAR-10 CNN training setup, which is too expensive to run multiple seeds of on CPU within the time budget._
- **`bias_correction_prevents_instability`** (ablation) — Removing the bias-correction terms from Adam (making it resemble RMSProp with momentum) causes training instabilities when beta2 is close to 1, especially early in training of a VAE. _A small VAE on a reduced dataset (e.g., downsampled MNIST) trained briefly on CPU can still reveal the qualitative instability caused by removing bias correction when beta2 is near 1._
- **`adam_equal_or_better_rmsprop`** (comparative) — Across the tested hyperparameter settings for training a VAE, Adam performs equal to or better than RMSProp regardless of hyperparameter setting. _A small VAE trained briefly on CPU across a few hyperparameter settings can plausibly preserve the relative ranking between Adam and RMSProp._
- **`adam_regret_bound`** (absolute) — Adam achieves a regret bound of O(sqrt(T)) in the online convex optimization framework, comparable to the best known bounds for this setting. _This is a theoretical asymptotic bound, not an empirical absolute number or comparison, and cannot be validated by running a small-scale experiment._

## How these experiments were run

> **These results were produced without container isolation.** The experiments ran in a restricted subprocess, with network access blocked and resources capped, but not inside a sandbox that can contain what it runs. Treat the results as a demonstration of the pipeline rather than as a trustworthy measurement, and re-run under Docker before relying on them.

## Limitations

Read these results narrowly.

- **A negative result here does not refute the paper.** These experiments run at a fraction of the
  original scale. An effect that disappears when the model, the data, or the training budget shrinks
  may still be real at full scale; that is precisely what reduced-scale testing cannot tell us.
- **A positive result is not a reproduction.** It says the direction of the claim survived
  shrinking, not that the paper's numbers were reproduced.
- **Seed counts are small.** With a handful of seeds per arm, statistical power is low. An
  inconclusive verdict usually means there was not enough evidence either way, not that the effect
  is absent.
- **Absolute claims are never testable this way** and are recorded without being run.
- The reduced experiments were written from the paper's description, so they may differ from the
  authors' implementation in ways that matter.
